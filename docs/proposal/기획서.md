## 0. 한눈에 보기

**한 문장 요약.** 공무원이 "청소년 버스 무료, 효과 있었어?"라고 물으면, Agent는 데이터부터 점검하고 비교 대상을 스스로 고른 뒤 반론까지 검증해서 1장짜리 판정서를 냅니다. 데이터에 이상이 있거나 근거가 부족하면 "판정 보류"라고 답하고, 무엇이 있으면 결론을 낼 수 있는지 알려 줍니다.

**왜 필요한가. 공개 데이터로 실제 정책 4건을 직접 분석해 보니, 단순 전후 비교로는 네 건 모두 틀린 결론이 나왔습니다.**

<!-- svg: figures/trap_A.svg -->

| 정책 | 단순 전후 비교의 결론 | 판정관이 확인한 것 |
|---|---|---|
| 청소년 버스 무료 (2025-08) | 청소년 승차 −76% → "정책 실패" | 무료 승차가 공개 데이터 집계에서 빠진 것으로 보임. 도 발표(하루 약 2만 2,800건)와 공개 데이터(약 2,700건)가 8.3배 차이 → **보류: 측정 단절 의심** |
| 1차 긴급재난지원금 (2020-05) | 사용 가능 업종 도민 소비 +5.1% → "효과 있음" | 비교군을 관광객으로 잡으면 방향이 음수로 뒤집힘(황금연휴 반등). 구분 가능한 최소 효과가 ±16%라 확정 불가 → **보류: 검정력 부족** |
| 중국 단체관광 재개 (2023-08) | 중국인 카드 소비 +106% → "효과 있음" | 정책 전부터 이어지던 회복 추세가 만든 값. 정책 시점에는 단절이 없음. 2023년 5~6월 외국인 데이터 결측 발견 → **보류: 사전추세 위반** |
| 사회적 거리두기 해제 (2022-04) | 도민 주점 소비 +95% → "효과 확실" | 정책 전 기준 기간에 영업이 사실상 멈춘 달(2021-08)이 섞여 기준선이 흔들림. 검증은 모두 통과했지만 구간이 넓음 → **보류: 기준 기간 이상** |

판정관은 네 건 모두에서 "왜 결론을 낼 수 없는지"와 "무엇이 있으면 낼 수 있는지"를 함께 냅니다. '효과 있음'을 제대로 내는지는 정답을 아는 합성데이터 6,400회로 따로 증명했습니다.

데이터가 늘어날수록 "작년보다 늘었다/줄었다"는 숫자는 쉽게 나옵니다. 그 숫자가 정책 효과인지, 데이터 문제나 다른 요인인지를 가려 주는 도구가 필요합니다.

**무엇이 다른가.**

| 흔한 데이터 활용 Agent | 정책 판정관 |
|---|---|
| 값을 **조회**하거나 미래를 **예측** | 이미 시행한 정책이 **효과가 있었는지 판정** |
| 데이터를 그대로 믿음 | **데이터부터 의심.** 정책 시점의 측정 단절과 결측을 먼저 점검 |
| "작년 대비 +12%" | "정책이 없었다면 어땠을지"와 비교한 순효과와 신뢰구간 |
| 결과를 보고 설계를 바꿀 수 있음 | **사전 등록.** 결과를 보기 전에 설계와 판정 기준을 잠그고, 바꾸면 기록이 남음 |
| 결과를 그대로 제시 | 반론을 스스로 만들어 검증하고, 통과하지 못하면 판정을 낮춤 |
| LLM이 숫자를 만들 수 있음 | **숫자는 검증된 통계 툴만** 만들고, LLM은 설계 판단·해석·서술만 담당 |
| "모르겠다"로 끝남 | **보류도 결과물.** 결재용 3줄 요약, 자료 요청 공문 초안, 다시 판정할 시점을 함께 냄 |

## 1. 구현 목표

### 1.1 분석 주제

**"제주도가 시행한 정책이 실제로 효과가 있었는가"를 제주데이터허브 데이터로 판정합니다.** 효과를 찾는 것만큼 **틀린 결론을 내지 않는 것**을 중요하게 봅니다.

제출 시 적용 사례는 실데이터 4건과 정확도 검증 1건입니다.

| 사례 | 정책 | 판정 질문 | 현재 분석 결과 | 보여 주는 기능 |
|---|---|---|---|---|
| A | 청소년 버스 무료 (2025-08-01) | 청소년의 버스 이용이 정책 때문에 늘었는가? | **판정 보류** (측정 체계 변경 의심) | 측정 단절 탐지, 외부 통계 대조, 필요한 데이터 안내 |
| B | 1차 긴급재난지원금 (2020-05) | 지원금 사용 가능 업종의 도민 카드 소비가 늘었는가? | **판정 보류** (검정력 부족: 사용 기간 평균 −4.9%, 구분 가능한 최소 효과 ±16%. 5월 단독은 +3.0%로 KDI와 방향·시점 일치) | 사전 등록 재판정, 비교군 오염 탐지, 위약검정, MDE 안내, 외부 연구(KDI)와 비교 |
| D | 중국 단체관광 재개 (2023-08-10) | 중국인 카드 소비가 다른 외국인 대비 늘었는가? | **판정 보류** (규칙 v2: 사전추세 위반, 추세 보정 시 방향 반대. 기록된 v1 판정은 원안 보류 / 수정안 조건부) | 사전 등록, 결측 탐지, 추세로 인한 과대 추정 차단 |
| E | 사회적 거리두기 전면 해제 (2022-04-18) | 제주도민의 주점 소비가 늘었는가? **(양성 대조)** | **판정 보류** (추정 +201%, 검증 C0~C4 모두 통과. 정책 전 기준 기간의 2021-08이 크게 벗어나 구간이 넓음) | 사전 등록(11-06 잠금), 큰 숫자를 그대로 믿지 않음, 보류 이유를 '기준 기간 이상'으로 설명 |
| C | 합성데이터 (효과를 심어 둔 데이터) | 심어 둔 효과를 정확히 복원하는가? | **합성 6,400회 시험**: 판정 허용 범위 95.7%, 없는 효과를 '효과 있음'이라 한 비율 2.4%, 측정 단절 경고 100% | 툴 정확도 리포트, '효과 있음' 판정 시연 |

실데이터 4건에서 '효과 있음'이 나오지 않은 것은 결과를 고치지 않았기 때문입니다. 사례 E는 효과가 있다고 널리 알려진 정책으로 일부러 고른 양성 대조였고, 결과를 본 뒤에도 설계를 바꾸지 않았습니다. '효과 있음' 판정이 제대로 작동하는지는 정답을 아는 합성데이터(사례 C)로 증명합니다.

### 1.2 AI를 활용한 데이터 분석 목표

1. **데이터 점검 자동화.** 정책 시점에 측정 방식이 바뀌었는지, 빠진 기간이 있는지를 효과 추정보다 먼저 확인합니다.
2. **분석 설계 자동화.** 비전문가가 하기 어려운 일(비교 대상 선정, 분석 방법 선택, 교란 요인 통제)을 Agent가 대신 설계하고, 결과를 보기 전에 잠급니다.
3. **반론 자동 검증.** "8월은 방학이라서 그런 것 아닌가?", "원래 회복 중이었던 것 아닌가?" 같은 대안 가설을 Agent가 스스로 만들고 데이터로 확인합니다.
4. **정직한 결론.** 효과 크기, 신뢰구간, "우연일 확률", "이 분석이 말할 수 없는 것"을 함께 제시합니다. 근거가 부족하면 결론을 미룹니다.
5. **재사용.** 정책 카드(무엇을, 언제부터, 누구에게/어디에)만 바꾸면 다른 정책에도 같은 엔진을 씁니다.

**성공 기준 (제출 시점에 측정해 결과 설명자료에 기재).**

| 기준 | 목표 | 현재 측정 (11-06) |
|---|---|---|
| 툴 정확도: 합성데이터에 심어 둔 효과의 복원 | 95% 신뢰구간 포함률 90% 이상, 효과 없는 데이터의 오탐률 10% 이하 | 포함률 92~99.5%. 오탐률 0~9.0%(최악: 정책 직전 시작된 추세) |
| 함정 탐지: 합성데이터에 심어 둔 측정 단절·결측·사전추세 위반 | 각 유형 탐지율 90% 이상 | 측정 단절 경고 100%(보류 83%), 결측 구간 100%, 사전추세 허용 범위 91~95% |
| 실데이터 판정 | 사례 A·B·D가 사전 등록한 규칙대로 같은 판정을 재현 | 엔진과 사례 스크립트의 핵심 수치 일치(B 0.029706, D β 0.996504) |
| 실행 시간: 질문 → 판정서 (센터 PC 사양) | 사례 1건 5분 이내 | 엔진 판정 1건 0.3초, 사례 5건 오프라인 실행 약 15초(개발 PC, 일 단위 버스 사례 A가 대부분). 센터 사양은 Windows 시험에서 측정 |
| 재현성: 같은 manifest로 재실행 | 핵심 수치 완전 일치 | Agent 실행 9건(오프라인 5, Claude 기록 4) 모두 수치·판정·판정서 문장 일치(Claude는 API 없이 응답 기록으로). 정확도 리포트도 완전 일치. 자동 시험 118개 |
| 오프라인 동작 | 인터넷 없이 템플릿 모드로 같은 판정 | Claude 기록이 있는 사례 4건 모두 두 모드의 판정 일치. API 실패 시 단계별 자동 대체(크레딧 소진 상황에서 실측). 새 정책도 '정책 카드 직접 만들기'로 키 없이 판정 |

### 2.2 핵심 기능

| 기능 | 설명 | 사용자가 보는 것 |
|---|---|---|
| **정책 카드** | 질문이나 보도자료에서 정책명, 시행일, 대상 집단·지역, 결과지표 후보를 뽑습니다. 사용자는 한 번만 확인합니다 | 세 칸짜리 카드: 무엇을 / 언제부터 / 누구에게·어디에 |
| **데이터 품질 점검** | 정책 시점 전후로 집계 방식이 바뀌었는지(구조적 단절, 다른 집단과의 이탈, 점진 이탈 패턴), 빠진 기간이 있는지, 공식 발표 수치와 맞는지 확인합니다 | "청소년 승차가 시행일부터 76% 감소. 일반 승객은 변화 없음. 도 발표와 8.3배 차이 → 측정 체계 변경 의심" |
| **사전 등록 잠금** | 결과를 보기 전에 비교 집단, 기간, 모형, 판정 기준을 문서로 고정하고 지문(해시)과 시각을 남깁니다. 이후 변경은 사유와 함께 기록하고, 원안 판정도 함께 보고합니다 | 잠금 시각, 변경 기록, 원안/수정안 판정 나란히 표시 |
| **비교 대상 자동 선정** | 정책 대상이 아닌 집단·업종 중 정책 이전 추세가 닮은 대상을 고릅니다 | 후보별 닮은 정도, 선택 이유 |
| **반사실 곡선** | 실제 값과 "정책이 없었다면" 곡선을 신뢰구간과 함께 그립니다 | 두 선 사이 간격이 곧 정책 효과 |
| **위약검정 시각화** | 가짜 시행일 수십 개로 같은 분석을 반복합니다. 실제 시행일만 튀어 오르는지 봅니다 | 회색 선 여러 개와 굵은 선 1개, "우연일 확률 x%" |
| **반론 검증 로그** | Agent가 만든 대안 가설과 검증 결과를 보여 줍니다 | "가설: 원래 회복 중이었다 → 월별 효과 확인 → 정책 시점 단절 없음 → 판정 하향" |
| **4단계 판정 신호등** | 효과 있음 / 효과 없음 / 조건부 / 판정 보류 | 색, 아이콘, 글자, 한 줄 결론 |
| **판정에 필요한 데이터 안내** | 보류일 때 현재 구분 가능한 최소 효과(MDE)와 결론에 필요한 데이터·기간을 알려 줍니다. 기준 기간에 크게 벗어난 시점이 있으면 기간이 아니라 그 시점을 이유로 듭니다 | "교통복지카드 승차 기록이 있으면 판정 가능", "지금은 ±16% 미만 효과를 구분할 수 없음"(사례 B) |
| **단순 비교였다면** | 대조·계절 보정·검증 없이 대상만 시행 전후로 비교한 값을 판정서 맨 위에 나란히 둡니다 | "단순 전후 비교 −76% → 정책 실패로 보였을 것" 대 "판정관: 판정 보류" |
| **다음 할 일** | 결재용 3줄 요약, 다시 판정할 시점(기간으로 풀리는지, 자료가 필요한지), 자료 요청 공문 초안(수신처·기한은 빈칸) | 복사·내려받기 버튼 |
| **정책 카드 직접 만들기** | 등록 사례가 아닌 정책도 데이터·시행일·대상만 고르면 판정합니다. 대조 집단은 Design Agent가 정책 전 유사도로 고릅니다(효과 가림). API 키가 필요 없습니다 | 목록에서 고르는 6칸 양식 |
| **Agent의 판단** | 단계마다 누가(Claude·규칙·사용자) 무엇을 왜 정했는지, 어떤 툴을 불렀는지 기록에서 보여 줍니다. 같은 사례의 오프라인 실행과 나란히 비교합니다 | 단계별 펼침 목록, 비교표 |
| **1장 판정서 PDF** | 판정, 단순 비교 대비, 근거, 한계를 1쪽에 정리합니다 | 결재 문서에 첨부 가능한 PDF |
| **원클릭 재실행** | 판정마다 데이터 지문, 사전 등록 해시, 시드, 툴·LLM 버전, 사건 달력 기준일을 기록한 manifest를 남깁니다 | "지금 재실행해서 확인" 버튼 |

### 2.3 편의성

- **통계 지식이 필요 없습니다.** 사용자가 하는 일은 질문 입력(또는 정책 카드 직접 만들기)과 정책 카드 확인 두 가지입니다. 이중차분 같은 용어는 부록으로 내리고, 화면에는 "비교 대상", "정책이 없었다면" 같은 쉬운 말을 씁니다.
- **센터 PC에서 설치 없이 바로 실행됩니다.** 압축을 풀고 `실행.bat`을 누르면 브라우저에 화면이 열립니다. 인터넷이 없어도 동작합니다.
- **보류도 쓸모 있게 만듭니다.** "모르겠다"로 끝내지 않습니다. 어떤 데이터를 확보하면 결론이 나는지를 자료 요청 공문 초안으로 만들고, 기다리면 풀리는 경우에는 다시 판정할 시점을 알려 줍니다.
- **설치 없이 웹에서도 둘러볼 수 있습니다.** 공개 웹 데모(https://jverdict.streamlit.app)에서 기록된 판정서와 합성데이터 판정을 바로 볼 수 있습니다(허브 원자료는 싣지 않음).
- **판정 문장은 "권고"가 아니라 "근거"로 씁니다.** 결론을 단정하지 않고 판단 근거를 제공하는 문서로 설계합니다.

### 2.4 분석 결과 활용 방안

## 3. Agent 개발 구성

### 3.1 구조: 6개 역할과 가드레일

<div class="band">상태머신: 순서는 코드가 고정하고, 단계를 건너뛸 수 없습니다</div>
<div class="flow">
<div class="step"><b>① Policy Parser</b><span>정책 카드</span><i>사람 확인 1회</i></div><div class="arrow">→</div>
<div class="step key"><b>② Data Scout</b><span>지표 확정·품질 점검</span><i>측정 단절이면 보류로 직행</i></div><div class="arrow">→</div>
<div class="step key"><b>③ Design Agent</b><span>비교 설계·잠금</span><i>잠금 전에는 효과 값을 볼 수 없음</i></div><div class="arrow">→</div>
<div class="step"><b>④ Executor</b><span>툴 실행</span><i>오류 시 수정·재시도 최대 3회</i></div><div class="arrow">→</div>
<div class="step"><b>⑤ Skeptic</b><span>반론 검증</span><i>판정 하향 권한</i></div><div class="arrow">→</div>
<div class="step out"><b>⑥ Reporter</b><span>판정서 서술</span><i>"말할 수 없는 것" 문단 필수</i></div>
</div>

**상태머신 가드레일.** LLM이 순서를 정하지 않습니다. 단계는 코드로 고정되어 있고, 각 단계 안에서 LLM이 툴을 골라 호출합니다.
- Design Agent가 설계를 잠그기 전에는 Executor가 효과 추정 툴을 호출할 수 없습니다.
- Skeptic 단계를 거치지 않으면 판정서를 만들 수 없습니다.
- 잠근 뒤 설계를 바꾸면 변경 기록이 자동으로 남고, 원안 판정을 함께 보고해야 합니다.

### 3.2 역할별 목표와 판단 범위

| 역할 | 목표 | LLM이 판단하는 것 | 코드가 강제하는 것 |
|---|---|---|---|
| ① Policy Parser | 질문·보도자료를 정책 카드로 구조화 | 정책명, 시행일, 처치 집단·지역, 결과지표 후보 추출 | 카드 스키마 검증, 사람 확인 1회 |
| ② Data Scout | 결과지표 확정과 데이터 점검 | 지표 후보 중 정책과 관련이 큰 것 선택, 대조할 공식 통계 제안 | 커버리지·결측 점검, 측정 단절 검정 필수 실행. 단절이 확인되면 판정 상한을 '보류'로 고정 |
| ③ Design Agent | 비교 설계와 사전 등록 | 대조 집단과 방법 선택(이중차분 / 이벤트스터디 / 단절 시계열), 결측 시 대안 설계 | 효과 값을 가린 상태에서 설계, 잠금(해시·시각) 필수, 선택 이유 기록 |
| ④ Executor | 효과 추정 | 오류 메시지를 읽고 파라미터 수정 | 잠긴 설계대로만 실행, 검증된 툴만 호출, 재시도 3회 상한 |
| ⑤ Skeptic | 결과 반박 | **대안 가설 생성**(방학, 연휴, 관광 회복, 유가, 다른 정책 등)과 이를 검증할 툴 선택 | 위약검정·사전추세·민감도 최소 세트 필수 실행, 판정 규칙 적용 |
| ⑥ Reporter | 판정서 작성 | 쉬운 말 서술, 한계 문단, 필요한 데이터 안내 | 모든 숫자는 툴 결과에서 그대로 인용(서술 속 숫자 대조 검사) |

**LLM의 자율성이 실제로 쓰이는 곳.**
- Data Scout: 공개 데이터의 숫자를 공식 발표와 맞춰 볼 생각을 하고, 비교할 통계를 고릅니다. 사례 A에서 도 발표 누적 483만 건과 공개 데이터의 차이를 잡아낸 것이 이 단계입니다.
- Design Agent: 결측이 발견되면 분석 기간을 줄일지, 다른 비교 집단을 쓸지 결정하고 이유를 남깁니다. 사례 D에서 2023년 5~6월 결측을 보고 사전 기간을 수정한 것이 이 단계입니다.
- Skeptic: 정책 맥락을 읽고 반론을 만듭니다. 사례 B에서 "황금연휴 관광 반등이 비교군을 오염시켰다"는 반론, 사례 D에서 "원래 회복 중이었다"는 반론이 여기서 나옵니다.

### 3.3 판정 규칙 (코드로 고정, 규칙 v2)

| 판정 | 조건 |
|---|---|
| 🟢 효과 있음 | 판정용 신뢰구간이 0을 포함하지 않음 + 사전추세(C1)·위약검정(C2) 통과 + 민감도(C3) 3개 중 2개 이상 통과 |
| ⚪ 효과 없음 | 판정용 신뢰구간이 0을 포함 + 검정력 충분(MDE가 기준 효과보다 작음) |
| 🟡 조건부 | 신뢰구간이 0을 포함하지 않지만 검증 일부 실패, 또는 90% 수준 신호이고 민감도 사양이 모두 같은 방향 |
| 🔴 판정 보류 | MDE가 기준 효과보다 큼, 사전추세 심각(p<0.01, 추세 보정 후 유의하지 않음), C1·C2 모두 실패, 커버리지 부족, 또는 **측정 단절 의심** |

- **판정용 신뢰구간**은 분석적 구간과 위약 분포 구간 중 넓은 쪽입니다(가짜 시행일 19개 이상일 때). 처치 집단이 하나뿐이면 업종별 표준오차가 지나치게 좁아지므로, 집단 수준 격차 시계열로 표준오차를 다시 계산합니다.
- **C1 사전추세**는 p ≥ 0.10이고, 정책 전 추세를 연장했을 때 설명되는 몫이 효과의 50% 미만이어야 통과입니다. **C2 위약검정**은 가짜 시행일 순위 p < 0.05, 그리고 정책 대상이 아닌 집단의 가짜 효과가 실제 효과의 절반 미만이어야 통과입니다.
- **규칙 변경 기록.** v1(기획서 원안)은 사례 D 사전 등록에 썼습니다. v2는 사례 D에서 사전추세가 크게 깨져도 '조건부'가 나온 문제와, 합성데이터 정확도 측정에서 드러난 문제(대조 집단에만 생긴 사건을 효과로 오판)를 고친 것입니다. 실데이터 결과에 맞춰 바꾸지 않았고, 사례 D는 v1 판정을 그대로 두고 v2 판정을 나란히 보고합니다.

판정 보류일 때는 "현재 구분 가능한 최소 효과"와 "결론에 필요한 데이터·기간"을 반드시 함께 냅니다.

### 3.4 사용 모델

| 용도 | 모델 | 비고 |
|---|---|---|
| 정책 카드 추출, 데이터 점검 계획, 설계 판단, 반론 생성, 판정서 서술 | Claude API (`claude-sonnet-5-5`) | 외부 API. 집계 통계와 스키마만 전송하고 원자료는 보내지 않음 |
| 오프라인 대체 | **템플릿 모드** (LLM 없음) | 등록 사례 카드 또는 정책 카드 직접 만들기, 정책 전 유사도로 대조 선택, 사건 달력 기반 반론, 템플릿 서술. 판정 규칙은 같음 |

- 업종명 분류 같은 짧은 작업에 경량 모델을 쓰는 안을 검토했지만, 업종 분류는 규정 근거와 함께 표로 고정하는 편이 재현에 낫다고 보아 넣지 않았습니다.

- 판정에 쓰는 모든 숫자는 통계 툴이 계산합니다. LLM은 설계를 고르고 말로 옮기는 역할입니다. 사전 등록 설계가 있는 사례(B·D)는 두 모드의 수치까지 같습니다. 새 질문에서는 LLM이 대조 집단을 고르므로 수치가 달라질 수 있지만, 같은 판정 규칙을 적용합니다(실측: 사례 A에서 Claude가 '경로'를 대조로 골라 효과 값은 달랐고 판정은 같은 '보류').
- LLM 응답은 manifest에 캐시해 재실행 시 같은 서술을 재현합니다. 호출마다 토큰 사용량과 비용을 기록합니다. 실측: 사례 1건에 호출 6~10회, 약 $0.09~0.13, 40~70초.

### 3.5 Tool / API

Agent의 툴은 입력·출력 스키마가 정해진 파이썬 함수입니다. Claude 툴콜링과 템플릿 모드가 같은 함수를 씁니다. 툴마다 **쓸 수 있는 단계**가 정해져 있어, 다른 단계에서 부르면 코드가 거부합니다.

**LLM이 골라 부르는 툴 (7개)**

| 툴 | 기능 | 쓸 수 있는 단계 |
|---|---|---|
| `catalog_search` | 적재된 데이터셋 목록과 설명(기간, 집단, 단위) 검색 | Data Scout, Design |
| `dataset_profile` | 집단별 기간·관측 수·평균 규모. **정책 시행일 이전 기간만** 요약(효과 가림) | Data Scout, Design |
| `official_stats` | 대조할 공식 발표 수치 목록(출처 포함) | Data Scout, Design |
| `quality_check` | 측정 단절 진단(방향 모순, 비현실적 크기, 외부 통계 불일치, 분류 변경)과 커버리지 점검. 단절이 의심되지 않으면 변화 크기를 가림 | Data Scout (**반드시 1회**, 안 부르면 코드가 실행) |
| `pick_controls` | 대조 후보가 정책 전 기간에 대상과 얼마나 비슷하게 움직였는지(상관, 격차 변동, 격차 추세) | Design |
| `event_calendar` | 기간 안의 사건(명절, 방학, 코로나19, 다른 지원금, 데이터 결측)과 출처. 재실행은 원래 실행 날짜의 달력을 씀 | Design, Skeptic |
| `extra_check` | 반론 검증: 잠긴 설계에서 한 가지만 바꿔 재추정(대체 대조, 기간 변경, 기간 제외, 가짜 처치). 성립 여부는 코드가 정함 | Skeptic (**잠금 뒤에만**) |

**코드가 반드시 실행하는 단계 (LLM이 건너뛸 수 없음)**

| 단계 | 기능 |
|---|---|
| 사전 등록 잠금 | 설계 문서·설계 JSON의 SHA-256과 시각 기록. 실행 직전 다시 대조하고, 다르면 멈춤 |
| 효과 추정 | 단절 시계열(대상/대조 격차, 계절 차분, 월 단위 AR(1)·일 단위 HAC+fixed-b), 업종 패널 이중차분·이벤트스터디 |
| 검증 세트 | C0 데이터 품질, C1 사전추세, C2a 시점 위약(가짜 시행일), C2b 공간 위약(가짜 처치 집단), C3 민감도, C4 이중 계산(pandas·SQL) |
| 검정력 | 구분 가능한 최소 효과(MDE), 필요한 사후 기간, 기준 기간 이상 시점 |
| 판정 규칙 v2 | 위 결과로 4단계 판정. Skeptic 반론이 성립하면 하향 |
| 서술 숫자 대조 | 판정서 속 숫자가 툴 결과에 없으면 다시 쓰게 함 |
| 판정서·재실행 기록 | 1장 PDF, 단순 비교 대비, 다음 할 일, manifest(데이터 지문, 코드 지문, LLM 응답 기록) |

외부 API: Claude API(선택, 인터넷 필요), 제주데이터허브 정류소 API(사전 내려받기, 실행 시 불필요).

### 3.6 오류 복구와 안전장치

- 툴 오류가 나면 Executor가 오류 메시지를 읽고 파라미터를 고쳐 최대 3회 재시도합니다. 그래도 실패하면 해당 분석을 제외하고 판정서에 기록합니다.
- 서술 속 숫자가 툴 결과와 다르면 Reporter 출력을 거부하고 다시 쓰게 합니다.
- 사전 등록 문서의 해시가 잠금 기록과 다르면 분석을 멈춥니다.
- API 키는 `.env`로만 받고 화면·로그·오류 메시지에 출력하지 않습니다. 키가 들어간 URL은 오류 메시지에서 지웁니다.
- 원인을 단정하지 않습니다. 데이터 품질 문제는 "측정 체계 변경 의심"으로 쓰고, 확인 방법을 함께 적습니다.

### 4.2 수집·전처리

1. **적재.** 허브에서 내려받은 CSV를 DuckDB로 줄 단위로 읽어 파케이 파일로 바꿉니다. 정류소명에 따옴표 없는 쉼표가 섞여 있어, 일반 CSV 파서 대신 파일별 정규식으로 파싱합니다. 현재 버스 4종 약 2,970만 행을 거부 행 0건으로 적재하며, 시간은 약 4.5초입니다. 파일마다 읽은 행, 거부 행, 기간을 적재 보고서로 남깁니다.
2. **정류소 API.** 페이지 단위(100건)로 내려받아 정류소 ID로 중복을 없앤 뒤 CSV로 저장합니다. 실행 시점에는 인터넷이 필요 없습니다.
3. **카드 데이터 정제.** 성별을 합산하고, 업종명 인코딩 오류(예: '기타음?식료품위주종합소매업')를 원래 업종에 합칩니다. 계절성은 2019년 같은 달 대비 로그 비율(또는 전년 같은 달 대비 로그 증가율)로 걸러 냅니다.
4. **업종 분류.** 지원금 사용처 규정(보도자료)을 근거로 43개 업종을 사용 가능 24 / 불가 2 / 불확실 17로 나누고, 근거를 표로 남깁니다. 불확실 업종은 주분석에서 빼고 민감도 분석에만 넣습니다.
5. **품질 점검.** 분석 전에 전체·집단 결측, 부분 집계일, 분류 신설을 자동 점검하고, 문제가 있는 기간은 분석에서 뺍니다. 실제로 2023년 5~6월 외국인 4개 집단 결측, 2022년 104일 전체 결측, 부분 집계일 126일, 2025-01 '기타' 분류 신설(어린이 재분류 의심)을 이 단계에서 찾았습니다.
6. **사전 등록.** 결과 값을 보기 전에 기간, 비교 집단, 모형, 판정 기준을 문서로 잠급니다.

### 4.3 이용조건과 개인정보

- 제주데이터허브의 이용약관과 데이터별 이용조건을 따릅니다. 데이터별 이용조건은 데이터 활용 명세에 그대로 옮겨 적습니다.
- **제출 zip(센터 제출용)**: 분석을 재현할 가공 파일(파케이)과 10MB 이하 원본(카드 파일 등)을 넣습니다. 1GB 버스 원본은 넣지 않고, 원본 지문과 가공 파일 지문을 짝지은 기록(`_sources.json`)으로 같은 데이터임을 확인합니다.
- **공개 저장소·웹 데모**: 허브의 재배포 조건을 확인하지 못해 원본과 가공 파일을 모두 싣지 않습니다. 판정 기록(집계 비율·검정 결과)과 내려받는 방법만 공개합니다.
- 사용하는 허브 데이터는 모두 집계 데이터라 개인 식별 정보가 없습니다. 화면과 판정서에는 개별 칸의 인원 수를 싣지 않고, 집단 간 비교의 변화율과 검정 결과만 보여 줍니다. Claude에도 집계 통계만 보냅니다.
- 대회 규칙에 따라 결과물은 제주빅데이터센터에 귀속되며, 비영리 목적으로만 씁니다.

### 5.4 센터 실행환경

- **최소사양 대응(i7-8700 / GTX 1060 / RAM 32GB).** 모든 분석은 CPU로 동작하며 GPU가 필요 없습니다. 적재 후 데이터는 파케이 약 65MB이고, 분석에 필요한 메모리는 수 GB 이내입니다.
- **설치가 필요 없습니다.** Windows용 Python(python.org 공식 파일, 지문 대조)과 패키지를 미리 풀어 넣은 묶음입니다. 압축을 풀고 `실행.bat`을 누르면 됩니다. 인터넷·관리자 권한이 필요 없습니다.
- **설치 점검.** `점검.bat`을 실행하면 이 PC에서 사례 5건을 새로 판정해 제출본 기록과 같은 수치가 나오는지 1~2분 안에 확인하고, 보고서를 남깁니다. Claude 실행 기록도 API 없이 다시 돌려 봅니다.
- **실행.** `실행.bat` → 로컬 브라우저에서 화면이 열립니다(외부 접속 없음).

API 키는 `.env` 파일로만 받으며, 제출물에는 키가 들어가지 않습니다(`.env.example`만 포함). 묶음을 만들 때 `.env` 파일이 없는지, 실제 키 값과 키 형식 문자열이 0건인지 자동으로 검사합니다. 하나라도 걸리면 압축하지 않습니다.

### 5.7 한계와 대응

| 한계 | 대응 |
|---|---|
| 실데이터 4건에서 '효과 있음' 판정이 없음. 양성 대조(E)도 보류 | 결과를 맞추려고 설계를 바꾸지 않음. E의 보류 원인(기준 기간의 영업 중단 달)을 진단해 판정서가 그 이유를 말하도록 보강. '효과 있음' 판정의 정확도는 합성데이터로 증명 |
| 공개 웹 데모에는 실데이터가 없음 | 허브 재배포 조건 미확인. 웹 데모는 기록된 판정서와 합성데이터 판정만, 실데이터 판정은 설치 묶음에서 |
| 공개 데이터는 월 단위·단일 카드사 등 해상도가 낮아 검정력이 부족함 | MDE로 "구분 가능한 최소 효과"를 함께 보고하고, 센터 일 단위 데이터 연계를 확장 계획에 둠 |
| 데이터 품질 문제(무료 승차 누락 의심, 외국인 결측)의 원인을 확인할 수 없음 | 원인을 단정하지 않고 "의심"으로 표기하며, 제공처 확인 방법을 판정서에 씀 |
| 청소년 무료 시행이 8월(방학)과 겹침 | 측정 체계가 확인되면 전년 동기 대비 변화로 한 번 더 비교하는 설계를 준비 |
| 데이터를 본 뒤의 설계 변경(사례 B 비교군 교체) | 사후 결정임을 판정서에 명시하고 처음 설계의 결과를 함께 보고. 엔진 재판정은 설계를 먼저 잠근 뒤 실행(열람 사실 고지) |
| 처치 집단이 하나(중국인 등)라 업종별 표준오차가 지나치게 좁아짐 | 집단 수준 격차 시계열로 표준오차를 다시 계산하고 위약 분포 구간과 비교해 넓은 쪽을 씀 |
| 인과 해석의 가정(평행추세 등)은 검정으로 완전히 증명할 수 없음 | 가정과 검정 결과를 판정서에 쓰고, 이 분석이 말할 수 없는 것을 별도 문단으로 기재 |
