## 0. 한 장 요약

**정책 판정관은 "정책이 효과가 있었는가"를 스스로 설계·검증해 판정하고, 근거가 부족하면 결론을 미루는 AI Agent입니다.** 제주데이터허브 공개 데이터로 실제 정책 4건과 정답을 아는 합성데이터 1건에 적용했습니다.

| 사례 | 단순 전후 비교 | 정책 판정관 | 판정 근거 |
|---|---|---|---|
| A 청소년 버스 무료 (2025-08-01) | −76.0% → "정책 실패" | 🔴 **판정 보류** | 측정 단절 의심(강): 정책 대상만 급감, 도 발표와 8.3배 차이, 파일 4종 모두 같은 결론 |
| B 1차 긴급재난지원금 (2020-05) | +5.1% → "효과 있음" | 🔴 **판정 보류** | 추정 −4.9%(판정 구간 −17.0% ~ +9.0%). 구분 가능한 최소 효과 ±16.0%로 검정력 부족 |
| D 중국 단체관광 재개 (2023-08) | +105.8% → "효과 있음" | 🔴 **판정 보류** | 사전추세 크게 깨짐(p=9.9×10⁻⁷). 추세를 보정하면 방향이 반대 |
| E 사회적 거리두기 해제 (2022-04-18), 양성 대조 | +94.8% → "효과 확실" | 🔴 **판정 보류** | 검증 C0~C4는 모두 통과. 그러나 기준 기간의 2021-08이 크게 벗어나 판정 구간 −66% ~ +2586% |
| C 합성데이터 (정답 +22.1%) | +35.5% (계절 때문에 과대) | 🟢 **효과 있음(증가)** | 추정 +19.6%(판정 구간 +15.6% ~ +25.2%)가 정답을 포함. 검증 6개 모두 통과 |

| 지표 | 결과 |
|---|---|
| 틀린 결론을 피했는가 | 실데이터 4건 모두 단순 비교의 결론과 달랐습니다. 판정관은 판정 보류의 이유와 필요한 자료를 함께 냈습니다 |
| 정확도(합성 6,400회) | 받아들일 만한 판정 95.7%, 없는 효과를 '효과 있음'이라 한 비율 2.4%, 방향을 반대로 판정 0%, 측정 단절 탐지 100% |
| 재현성 | 실행 9건(오프라인 5, Claude 기록 4) 모두 수치·판정·판정서 문장 일치. Claude 기록은 API 없이 응답 기록으로 재실행 |
| 실행 환경 | 설치·인터넷·관리자 권한 없이 Windows에서 `실행.bat`. 오프라인 실행 사례 5건 약 15초(개발 PC) |
| 자동 시험 | 118개 통과(자료가 없는 공개본은 113개 통과, 자료 필요한 5개 건너뜀) |

## 1. 문제 정의

### 1.1 무엇이 문제인가

데이터가 늘어날수록 "작년보다 늘었다/줄었다"는 숫자는 쉽게 나옵니다. 그 숫자가 정책 때문인지, 데이터 문제나 다른 요인 때문인지는 쉽게 가려지지 않습니다. 이번에 공개 데이터로 실제 정책 4건을 직접 분석해 보니, 단순 전후 비교는 **네 건 모두 틀린 결론**을 냈습니다.

<!-- svg: ../proposal/figures/trap_A.svg -->

- **A 청소년 버스 무료화.** 시행일부터 청소년 승차가 76% 줄었습니다. 그대로 보고하면 "무료화 실패"입니다. 하지만 정책 대상(청소년·어린이)만 줄었고 다른 유형은 그대로였습니다. 도 발표(하루 약 22,783건)와 공개 데이터(약 2,745건)도 8.3배 차이가 납니다. 무료 승차가 공개 집계에서 빠진 것으로 보입니다.
- **B 재난지원금.** 비교군을 어떻게 잡느냐에 따라 방향이 뒤집힙니다(관광객과 비교하면 음수, 도민 내부 비교는 양수).
- **D 중국 단체관광.** 소비가 두 배로 늘었지만, 정책 전부터 이어지던 회복 추세가 만든 값이었습니다.
- **E 거리두기 해제.** 주점 소비가 크게 늘었지만, 비교 기준이 된 기간에 영업이 사실상 멈춘 달이 섞여 있었습니다.

### 1.2 누구를 위한 것인가

| 사용자 | 필요 |
|---|---|
| 도청 정책 부서 | 정책 효과를 보고하기 전에 숫자가 정책 효과인지 확인 |
| 도의회·정책보좌관 | 질의 전 "늘었다/줄었다"의 사실 확인 |
| 연구용역 발주 부서 | 과업지시서에 비교 집단·필요 기간을 미리 반영 |
| 제주빅데이터센터 | 정책 판정 서비스 운영, 공개 데이터 품질 감시 |

### 1.3 목표

1. 효과를 찾는 것만큼 **틀린 결론을 내지 않는 것**을 중요하게 봅니다.
2. 통계 지식이 없어도 질문 한 줄로 판정서를 받게 합니다.
3. 결론을 낼 수 없으면 **무엇이 있으면 낼 수 있는지**를 알려 줍니다.
4. 누가 다시 해도 같은 결과가 나오게 합니다.

## 2. Agent 구조

### 2.1 6개 역할과 가드레일

<div class="step key"><b>② Data Scout</b><span>계열 정의·품질 점검</span><i>측정 단절이면 상한 '보류'</i></div><div class="arrow">→</div>
<div class="step key"><b>③ Design Agent</b><span>대조·기간·방법 선택</span><i>효과 값을 볼 수 없음</i></div><div class="arrow">→</div>

<div class="step"><b>⑤ Skeptic</b><span>반론 세우고 검증</span><i>판정 하향 권한</i></div><div class="arrow">→</div>
<div class="step out"><b>⑥ Reporter</b><span>판정서 서술</span><i>숫자 대조 검사</i></div>

| 원칙 | 구현 |
|---|---|
| 숫자는 툴이, 말은 LLM이 | 추정·검증·판정은 결정론적 코드(`jverdict.causal`). LLM은 설계 판단·반론·서술만. 판정서 속 숫자가 툴 결과에 없으면 다시 쓰게 함 |
| 결과를 보기 전에 잠금 | 설계 단계의 툴은 시행일 이전 자료만 돌려줌. 잠금 전에는 효과 추정 툴을 부를 수 없음(코드가 거부) |
| 데이터부터 의심 | 품질 점검은 LLM이 부르지 않아도 코드가 반드시 실행. 측정 단절이 의심되면 판정 상한을 '판정 보류'로 고정 |
| 보류도 결과물 | 필요한 자료, 다시 판정할 시점, 자료 요청 공문 초안을 함께 냄 |

### 2.2 툴

| LLM이 골라 부르는 툴 (7개) | 기능 |
|---|---|
| `catalog_search`, `dataset_profile` | 데이터셋 찾기, 집단별 요약(정책 전 기간만) |
| `official_stats` | 대조할 공식 발표 수치 |
| `quality_check` | 측정 단절 진단과 커버리지 점검(반드시 1회) |
| `pick_controls` | 대조 후보의 정책 전 유사도(상관·격차 변동·격차 추세) |
| `event_calendar` | 같은 시기의 사건(명절·방학·코로나19·지원금·데이터 결측) |
| `extra_check` | 반론 검증용 재추정(대체 대조·기간 변경·기간 제외·가짜 처치). 잠금 뒤에만 |

코드가 반드시 실행하는 단계는 다음과 같습니다.
- 잠금 검증
- 추정: 단절 시계열, 업종 패널 이중차분
- 검증 세트: C0 데이터 품질, C1 사전추세, C2a 시점 위약, C2b 공간 위약, C3 민감도, C4 이중 계산
- 검정력(MDE)
- 판정 규칙 v2
- 서술 숫자 대조
- 판정서와 재실행 기록

### 2.3 실행 방식

| 방식 | 판단 주체 | 필요한 것 |
|---|---|---|
| 오프라인(템플릿) | 규칙 기반 Agent | 없음(인터넷·키 불필요) |
| Claude | `claude-sonnet-5-5`(툴콜링) | API 키. 실행 1건 약 $0.09~0.13, 40~70초 |
| 재실행 | 저장된 응답 기록 | 없음(API를 부르지 않음) |

Claude 단계가 실패하면 그 단계만 템플릿으로 자동 대체하고 기록에 남깁니다. API 크레딧이 떨어진 상황(사례 C)에서 실제로 확인했습니다.

## 4. 실행 결과

모든 수치는 `outputs/runs/<실행>/`의 기록에서 옮겼습니다. 요약표는 `outputs/runs/_summary.md`에 있습니다.

### 4.1 사례 A: 청소년 버스 무료화 (2025-08-01) → 판정 보류

- **데이터.** 이용자 유형별 버스정류소 이용 인원(일 단위). 대조 집단은 일반 승객이고, 계절 차분은 3년입니다.
- **결과.** 추정 −77.0%(판정 구간 −81.8% ~ −71.0%)로 크고 분명하지만, 방향이 정책 목적과 반대입니다.
- **측정 단절 진단: 의심(강).** 근거는 세 가지입니다.
  - 방향 모순
  - 비현실적 크기
  - 외부 통계 불일치: 도 발표의 8.3배 차이
- **파일 4종이 같은 결론.**

  | 파일 | 청소년 변화 |
  |---|---|
  | 정류소별 | −76% |
  | 노선별 | −63% |
  | 시간대별 | −67% |
  | 월별 패널티 | −85% |

  정책 대상이 아닌 경로·장애 유형에는 단절이 없습니다.
- **시간대 모양.** 청소년 감소(일반 대비)가 통학 시간대(07~09시 −69%)만이 아니라 새벽(−80%)과 밤(−69%)까지 고릅니다. 이용 행동 변화보다 집계 누락에 가까운 모양입니다.
- **필요한 데이터.**
  - 교통복지카드(무료) 승차 기록이 포함된 이용자 유형별 승차 자료
  - 2025-08-01 전후 분류 기준 변경 이력
- **Claude 실행과 비교.** Claude는 대조로 '경로'를 골랐습니다(정책 전 상관 0.9868로 일반보다 높음). 추정 −75.6%, 판정은 같은 '보류'입니다. LLM 호출 9회, $0.128이었습니다.

### 4.2 사례 B: 1차 긴급재난지원금 (2020-05) → 판정 보류

- **설계.** 사전 등록 문서(`docs/prereg/case_relief2020_engine.md`)를 그대로 썼습니다. 대상은 도민 × 사용 가능 업종 24개, 대조는 도민 × 사용 불가 업종이고, 법인은 공간 위약으로 썼습니다.
- **결과.** 사용 기간(5~8월) 평균 −4.9%(판정 구간 −17.0% ~ +9.0%)입니다. 구분 가능한 최소 효과가 ±16.0%라 기준 효과 10%를 가릴 수 없습니다(검정력 부족). 시점 위약검정(C2a)도 통과하지 못했습니다.
- **해석.** 5월 단독은 +3.0%로 KDI 연구와 방향·시점이 맞습니다. 하지만 월 단위·단일 카드사 자료로는 확정할 수 없습니다. 첫 분석의 판정 후보였던 '조건부'는 사전 등록한 엔진 재판정으로 '보류'가 되었습니다.
- **다시 판정할 때.** 끝난 정책이라 기다려도 관측이 늘지 않습니다. 일 단위나 전체 카드사 자료가 필요합니다.

### 4.3 사례 D: 중국 단체관광 재개 (2023-08-10) → 판정 보류

- **설계.** 사전 등록 문서(수정 1)를 썼습니다. 업종 패널 이중차분이고, 대조는 일본·동남아·기타외국입니다. 2019년 같은 달 기준이고, 업종 × 월 고정효과를 넣었습니다.
- **결과.** 주분석 +170.9%였지만 사전추세가 크게 깨졌습니다(p=9.9×10⁻⁷). 추세를 보정하면 −75.8%로 방향이 반대입니다. 민감도(C3)도 실패했습니다.
- **해석.** 정책 시점의 단절이 아니라 기존 회복 추세가 만든 값입니다.
- **데이터 문제.** 2023-05~06 외국인 4개 집단 결측을 자동으로 찾았습니다.
- **판정 기록.** 원래 등록(규칙 v1) 판정과 수정안 판정을 나란히 기록합니다.
- **Claude 실행.** 반론을 4개 세웠습니다(재개 직후 단기 효과, 일본 단독 비교, 사전 기간 말 회복기 제외 등). 판정은 같은 '보류'입니다.

### 4.4 사례 E: 사회적 거리두기 전면 해제 (2022-04-18) → 판정 보류 (양성 대조)

- **왜 했나.** 실데이터에서 '효과 있음'이 한 번도 나오지 않아서, 효과가 있다고 널리 알려진 정책을 일부러 골랐습니다.
- **사전 등록.** `docs/prereg/case_distancing_2022.md`, 2026-11-06 00:30 잠금. 결과를 본 뒤 설계는 바꾸지 않았습니다.
- **설계.** 제주도민 × 주점(일반유흥·기타 주점)을 식료품 소매 5업종과 비교했습니다. 사전 12개월, 사후 6개월입니다. 과거 같은 달도 방역 기간이라 계절 차분은 쓰지 않았고, 가짜 시행일은 방역 기간 밖에서만 뽑았습니다.
- **결과.** 추정 +201.2%였고 검증 C0~C4는 모두 통과했습니다. 시점 위약에서도 가짜 34개 중 실제가 가장 컸습니다(p=0.029). 그러나 판정 구간이 −66.2% ~ +2586.4%로 넓어 규칙상 '보류'입니다.
- **원인.** 기준 기간 안의 2021-08(거리두기 4단계 무렵)에 주점 결제가 거의 사라졌습니다. 대상/대조 로그 격차로 보면 사전 중앙값보다 4.44 낮습니다. 이 한 달이 기준선과 분산을 함께 흔들었습니다.
- **판정서의 설명.** "사후 5524개월 필요" 같은 엉뚱한 안내 대신 "기준 기간의 이상 시점(2021-08)을 먼저 확인"이라고 쓰도록 보강했습니다.
- **보조 확인(사전 등록 밖, 판정에 쓰지 않음).** 다른 파일(시간대별 카드 이용 금액)에서 도민 소비 중 밤 시간대 비중을 봤습니다.

  | 시점 | 밤 비중 |
  |---|---|
  | 2019년(코로나 전) | 11.5% |
  | 해제 직전 | 4.4% |
  | 해제 뒤 | 9.6% |

  늦은 시간 소비가 해제 뒤 두 배 넘게 회복했습니다. 따라서 E의 '보류'는 효과가 없다는 뜻이 아닙니다. 기준 기간이 오염되어 판정관이 보수적으로 멈춘 것입니다. 실데이터에서 '효과 있음'을 낸 사례는 아직 없고, 이 점을 그대로 보고합니다.

### 4.5 사례 C: 합성데이터 (정답 +22.1%) → 효과 있음(증가)

- **데이터.** 실데이터 변동에 맞춘 합성 버스 데이터입니다. 2024-03-04에 청소년 +22.1%를 심어 두었고, 정답은 판정 뒤에만 공개합니다.
- **결과.** 추정 +19.6%(판정 구간 +15.6% ~ +25.2%)로 판정 구간이 정답을 포함합니다. 검증 6개 모두 통과했고, 구분 가능한 최소 효과는 ±6.0%입니다.
- **단순 전후 비교와의 차이.** 단순 비교는 +35.5%입니다. 시행 전후 계절 차이까지 효과로 셌기 때문입니다.

## 5. 검증과 한계

### 5.1 정확도 (정답을 아는 합성데이터)

| 항목 | 결과 | 규모 |
|---|---|---|
| 받아들일 만한 판정(정답에 비추어 틀리지 않음) | 95.7% | 인과 판정 12개 시나리오 × 200회 = 2,400회 |
| 효과가 없는데 '효과 있음' | 2.4% | 같은 2,400회 |
| 효과가 있는데 '효과 없음' | 0.1% | 같은 2,400회 |
| 방향을 반대로 | 0% | 같은 2,400회 |
| 검정력 곡선 | +5% 효과 41.5%, +10.5% 79% '효과 있음' | 1,400회 |
| 측정 단절 탐지(60~90% 누락) | 100% | 품질 점검 13개 시나리오 × 200회 = 2,600회 |
| 실제 효과를 측정 단절로 잘못 봄 | 0.125% | 같은 2,600회 |
| 가장 약한 지점: 기존 분류 사이 이동 | '의심' 11%, '확인 필요' 포함 67% | 같은 2,600회 |

정확도 측정에서 드러난 문제(대조 집단에만 생긴 사건을 효과로 오판 등)는 판정 규칙 v2로 고쳤습니다. 변경 이력은 코드 안에 기록했습니다.

### 5.2 재현성

- **재실행 대조.** 실행 9건 모두 핵심 수치·판정·판정서 문장이 같습니다. Claude 기록 4건은 API 없이 저장된 응답으로 재실행합니다.
- **지문 기록.** 판정마다 다음을 남깁니다.
  - 데이터 지문(원본·가공 파일 SHA-256)
  - 코드 지문
  - 사전 등록 지문
  - 시드
  - LLM 응답 기록
  - 사건 달력 기준일
- **보강한 문제.**
  - 같은 PC에서도 앞서 실행한 작업에 따라 부동소수 마지막 비트가 달라졌습니다 → 정규화 지문으로 해결
  - 사례를 하나 추가하자 기존 Claude 기록의 프롬프트가 바뀌었습니다 → 참고 사례 목록 고정으로 해결
  - 사건 달력이 늘어나 기존 기록과 어긋났습니다 → 원래 실행 날짜의 달력을 쓰게 해 해결
- **설치 점검.** 압축을 새로 푼 상태를 흉내 낸 점검에서 실패 0건이었습니다. Windows 실제 PC 시험은 최종 묶음으로 11-17에 하며, 결과는 제출 전 이 문서에 반영합니다.

### 5.3 한계

| 한계 | 대응 |
|---|---|
| 실데이터 4건 모두 '보류', '효과 있음' 실데이터 사례 없음 | 결과에 맞춰 설계를 바꾸지 않음. '효과 있음'의 작동은 합성데이터로 증명. E의 보조 확인은 효과의 존재를 시사 |
| 공개 데이터의 해상도(월 단위·단일 카드사)가 낮아 검정력 부족 | 구분 가능한 최소 효과를 함께 보고. 센터 일 단위 자료 연계를 확장 계획에 둠 |
| 측정 단절·결측의 원인을 데이터만으로 확인할 수 없음 | '의심'으로 표기하고 제공처 확인 방법을 판정서·품질 점검 보고에 적음 |
| 평행추세 등 인과 가정은 검정으로 완전히 증명할 수 없음 | 판정서마다 '이 분석이 말할 수 없는 것' 문단 |
| 사례 B의 비교군 교체는 데이터를 본 뒤의 결정 | 사후 결정임을 명시하고, 엔진 재판정은 설계를 먼저 잠근 뒤 실행(열람 사실 고지) |
| 오프라인 모드는 문장으로 된 새 질문을 해석하지 못함 | 정책 카드 직접 만들기로 새 정책을 판정 |
| 공개 웹 데모에는 실데이터 없음 | 허브 재배포 조건 미확인. 기록된 판정서와 합성데이터 판정만, 실데이터는 설치 묶음 |

## 6. 센터 활용 방안

### 6.1 바로 쓸 수 있는 것

1. **정책 판정 서비스.** 부서가 질문이나 정책 카드를 보내면 센터가 판정서를 발행합니다. 보류이면 자료 요청 공문 초안과 다시 판정할 시점을 함께 돌려줍니다. 판정마다 잠긴 설계와 재실행 기록이 남습니다. 그래서 감사·검증 때 "같은 판정 다시 만들기"가 됩니다.
2. **공개 데이터 품질 감시.** 새 데이터를 올릴 때 같은 품질 점검(`jverdict.quality`)을 돌리면, 집계 방식이 바뀐 날을 공개 전에 찾을 수 있습니다. 이번에 찾은 5건은 「허브 데이터 품질 점검 보고」로 별첨했습니다.
   - 청소년 무료화 시점의 측정 단절
   - 2025-01 '기타' 신설
   - 104일 결측
   - 부분 집계 126일
   - 외국인 2개월 결측
3. **연구용역 사전 설계.** 사전 등록 문서를 과업 산출물로 요구하고, 필요한 비교 집단·기간을 과업지시서에 미리 넣습니다.

### 6.2 확장

| 확장 | 내용 |
|---|---|
| 센터 내부 데이터 연계 | 일 단위 쓰레기·날씨·카드 전체 자료로 검정력 향상. 예: 재활용품 요일별 배출제(2027 존폐 결정)·상시배출 시범의 사전 평가 설계 |
| 추정 방법 | 합성통제, 회귀불연속, 집단별(연령·지역) 이질적 효과 |
| 지역 단위 | 정류소 → 읍면동 매핑(정류소 API 확보 완료)으로 지역 정책 판정 |
| 운영 | 판정 이력 관리, 부서별 요청·공유, 재판정 알림 |
