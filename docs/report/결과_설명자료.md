## 0. 한 장 요약

**정책 판정관은 "정책이 효과가 있었는가"를 스스로 설계·검증해 판정하고, 근거가 부족하면 결론을 미루는 AI Agent입니다.** 제주데이터허브 공개 데이터로 실제 정책 4건과 정답을 아는 합성데이터 2건에 적용했습니다.

| 사례 | 단순 전후 비교 | 정책 판정관 | 판정 근거 |
|---|---|---|---|
| A 청소년 버스 무료 (2025-08-01) | −76.0% → "정책 실패" | 🟣 **판정 보류** | 측정 단절 의심(강): 정책 대상만 급감, 도 발표와 8.3배 차이, 파일 4종 모두 같은 결론 |
| B 1차 긴급재난지원금 (2020-05) | +5.1% → "효과 있음" | 🟣 **판정 보류** | 추정 −4.9%(판정 구간 −17.0% ~ +9.0%). 구분 가능한 최소 효과 ±16.0%로 검정력 부족 |
| D 중국 단체관광 재개 (2023-08-10) | +105.8% → "효과 있음" | 🟣 **판정 보류** | 정책 전부터 회복 추세(사전추세 검정 p=9.9×10⁻⁷). 정책 전 시점이 3개뿐이라 추세와 정책 효과를 가를 수 없음 |
| E 사회적 거리두기 해제 (2022-04-18), 양성 대조 | +94.8% → "효과 확실" | 🟣 **판정 보류** | 실패한 검증은 없지만 기준 기간의 2021-08이 크게 벗어나 판정 구간이 −66% ~ +2586%로 넓음. **양성 대조에서 효과를 확인하지 못함**(사전 등록에서 정한 보고 문구) |
| C 합성데이터 (정답 +22.1%) | +35.5% (계절 때문에 과대) | 🟢 **효과 있음(증가)** | 추정 +19.6%(판정 구간 +15.6% ~ +25.2%)가 정답을 포함. 검증 6개 모두 통과 |
| F 합성데이터 2 (정책 효과 0, 같은 시기 행사) | +6.4% → "효과 있음" | 🟣 **판정 보류**(반론 하향) | 검증 6개를 모두 통과해 규칙 결과는 '효과 있음'. 반론 단계가 같은 시기 행사를 찾아 그 기간을 빼자 효과가 사라져(−1.0%) 판정을 낮춤 |

**판정 보류가 막은 것.** A는 −76%를 근거로 한 "무료화 실패" 보고를, B는 +5.1%를 근거로 한 "지원금 효과" 보고를, D는 +106%를 정책 효과로 돌리는 보고를 막았습니다. E는 효과가 있을 법한 정책이지만 공개 자료로는 확정할 수 없다는 사실을 그대로 냈습니다. 넷 모두 결론에 필요한 자료와 다시 판정할 시점을 함께 냈습니다.

| 지표 | 결과 |
|---|---|
| 단순 비교의 결론을 확정했는가 | 실데이터 4건 모두 단순 비교만으로는 확정할 수 없는 결론이었습니다. 판정관은 판정 보류의 이유와 필요한 자료를 함께 냈습니다 |
| 정확도(합성 인과 판정 2,400회) | 없는 효과를 '효과 있음'이라 한 비율 2.4%(시나리오별 최악 9.0%), 실제 효과에 '효과 있음' 83%(시계열)·74.5%(패널), 판정 보류 37.6%, 방향을 반대로 판정 0%. 효과가 없는데 '조건부'까지 포함해 방향을 말한 비율은 23.2%. 강한 측정 단절(60~90% 누락) 탐지 100% |
| 재현성 | 실행 12건(오프라인 6, Claude 실행 5, API 장애 대체 시연 1) 모두 수치·판정·판정서 문장 일치. Claude 기록은 API 없이 응답 기록으로 재실행 |
| 실행 환경 | 설치·인터넷·관리자 권한 없이 Windows에서 `실행.bat`. 오프라인 실행 사례 6건 약 15초(개발 PC). Windows 11 PC에서 실데이터 사례 1건 22.9초(11-08 실측) |
| 자동 시험 | 134개 통과(자료가 없는 공개본은 127개 통과, 자료 필요한 7개 건너뜀) |

## 1. 문제 정의

### 1.1 무엇이 문제인가

데이터가 늘어날수록 "작년보다 늘었다/줄었다"는 숫자는 쉽게 나옵니다. 그 숫자가 정책 때문인지, 데이터 문제나 다른 요인 때문인지는 쉽게 가려지지 않습니다. 이번에 공개 데이터로 실제 정책 4건을 직접 분석해 보니, 단순 전후 비교는 **네 건 모두 확정할 수 없는 결론**이었습니다. 그대로 보고했다면 넷 다 근거가 약한 결론이 되었을 것입니다.

<!-- svg: ../proposal/figures/trap_A.svg -->

- **A 청소년 버스 무료화.** 시행일부터 청소년 승차가 76% 줄었습니다. 그대로 보고하면 "무료화 실패"입니다. 하지만 정책 대상(청소년·어린이)만 줄었고 다른 유형은 그대로였습니다. 도 발표(하루 약 22,783건)와 공개 데이터(약 2,745건)도 8.3배 차이가 납니다. 무료 승차가 공개 집계에서 빠진 것으로 보입니다.
- **B 재난지원금.** 비교군을 어떻게 잡느냐에 따라 방향이 달라집니다. 관광객과 비교하면 음수이고, 도민 내부 비교(사용 가능 업종 대 불가 업종)는 사용 기간 평균 −4.9%로 0과 구분되지 않습니다.
- **D 중국 단체관광.** 소비가 두 배로 늘었지만, 정책 전부터 회복 추세가 뚜렷해 정책 효과와 구분할 수 없었습니다.
- **E 거리두기 해제.** 주점 소비가 크게 늘었지만, 비교 기준이 된 기간에 영업이 사실상 멈춘 달이 섞여 있었습니다.

### 1.2 누구를 위한 것인가

| 사용자 | 필요 |
|---|---|
| 도청 정책 부서 | 정책 효과를 보고하기 전에 숫자가 정책 효과인지 확인 |
| 도의회·정책보좌관 | 질의 전 "늘었다/줄었다"의 사실 확인 |
| 연구용역 발주 부서 | 과업지시서에 비교 집단·필요 기간을 미리 반영 |
| 제주빅데이터센터 | 정책 판정 서비스 운영, 공개 데이터 품질 감시 |

### 1.3 목표

1. 효과를 찾는 것만큼 **근거 없는 결론을 내지 않는 것**을 중요하게 봅니다.
2. 통계 지식이 없어도 질문 한 줄로 판정서를 받게 합니다.
3. 결론을 낼 수 없으면 **무엇이 있으면 낼 수 있는지**를 알려 줍니다.
4. 누가 다시 해도 같은 결과가 나오게 합니다.

## 2. Agent 구조

### 2.1 6개 역할과 가드레일

<div class="step out"><b>⑥ Reporter</b><span>판정서 서술</span><i>숫자 대조 검사</i></div>

| 원칙 | 구현 |
|---|---|
| 숫자는 툴이, 말은 LLM이 | 추정·검증·판정은 결정론적 코드(`jverdict.causal`). LLM은 설계 판단·반론·서술만. 판정서 속 숫자가 툴 결과에 없으면 다시 쓰게 함 |
| 결과를 보기 전에 잠금 | 설계 단계의 툴은 시행일 이전 자료만 돌려줌. 잠금 전에는 효과 추정 툴을 부를 수 없음(코드가 거부) |
| 데이터부터 의심 | 품질 점검은 LLM이 부르지 않아도 코드가 반드시 실행. 측정 단절이 의심되면 판정 상한을 '판정 보류'로 고정 |
| 보류도 결과물 | 필요한 자료, 다시 판정할 시점, 자료 요청 공문 초안을 함께 냄 |

### 2.2 툴

| LLM이 골라 부르는 툴 (7개) | 기능 |
|---|---|
| `catalog_search`, `dataset_profile` | 데이터셋 찾기, 집단별 요약(정책 전 기간만) |
| `official_stats` | 대조할 공식 발표 수치 |
| `quality_check` | 측정 단절 진단과 커버리지 점검(반드시 1회) |
| `pick_controls` | 대조 후보의 정책 전 유사도(상관·격차 변동·격차 추세) |
| `event_calendar` | 같은 시기의 사건(명절·방학·코로나19·지원금·데이터 결측) |
| `extra_check` | 반론 검증용 재추정(대체 대조·기간 변경·기간 제외·가짜 처치). 잠금 뒤에만 |

코드가 반드시 실행하는 단계는 다음과 같습니다.
- 잠금 검증
- 추정: 단절 시계열, 업종 패널 이중차분
- 검증 세트: C0 데이터 품질, C1 사전추세, C2a 시점 위약, C2b 공간 위약, C3 민감도, C4 이중 계산
- 검정력(MDE)
- 판정 규칙 v2
- 서술 숫자 대조
- 판정서와 재실행 기록

### 2.3 실행 방식

| 방식 | 판단 주체 | 필요한 것 |
|---|---|---|
| 오프라인(템플릿) | 규칙 기반 Agent | 없음(인터넷·키 불필요) |
| Claude | `claude-sonnet-5-5`(툴콜링) | API 키. 실행 1건 LLM 호출 7~10회, $0.10~0.14, 42~89초(사례 A·B·D·E·F 실측) |
| 재실행 | 저장된 응답 기록 | 없음(API를 부르지 않음) |

Claude 단계가 실패하면 그 단계만 템플릿으로 자동 대체하고 기록에 남깁니다. 개발 중 API 크레딧이 떨어졌을 때(11-03) 실제로 겪었고, 제출 기록 `case-C-claude-apifail`은 잘못된 키로 같은 상황을 재현한 시연입니다.

## 4. 실행 결과

모든 수치는 `outputs/runs/<실행>/`의 기록에서 옮겼습니다. 요약표는 `outputs/runs/_summary.md`에 있습니다.

### 4.1 사례 A: 청소년 버스 무료화 (2025-08-01) → 판정 보류

- **데이터.** 이용자 유형별 버스정류소 이용 인원(일 단위). 대조 집단은 일반 승객이고, 계절 차분은 3년입니다(오프라인 실행 기준).
- **결과.** 추정 −77.0%(판정 구간 −81.8% ~ −71.0%, 오프라인)로 크고 분명하지만, 방향이 정책 목적과 반대입니다.
- **측정 단절 진단: 의심(강).** 근거는 세 가지입니다.
  - 방향 모순
  - 비현실적 크기
  - 외부 통계 불일치: 도 발표의 8.3배 차이
- **파일 4종이 같은 결론.**

  | 파일 | 청소년 변화 |
  |---|---|
  | 정류소별 | −76% |
  | 노선별 | −63% |
  | 시간대별 | −67% |
  | 월별 패널티 | −85% |

  정책 대상이 아닌 경로·장애 유형에는 단절이 없습니다.
- **시간대 모양.** 청소년 감소(일반 대비)가 통학 시간대(07~09시 −69%)만이 아니라 새벽(−80%)과 밤(−69%)까지 고릅니다. 이용 행동 변화보다 집계 누락에 가까운 모양입니다.
- **필요한 데이터.**
  - 교통복지카드(무료) 승차 기록이 포함된 이용자 유형별 승차 자료
  - 2025-08-01 전후 분류 기준 변경 이력
- **Claude 실행과 비교.** Claude는 효과 값을 보지 않고 '일반'을 주 대조로, '경로'·'장애'를 대체 대조로 두었고, 2025-01 '기타' 유형 신설(분류 변경)과 설 연휴를 시점 위약에서 빼도록 지정했습니다. 계절 차분도 3년이 아니라 2년을 골랐습니다. 그래서 추정이 −76.5%(−81.9% ~ −70.4%)로 오프라인과 조금 다르고, 판정은 같은 '보류'입니다. LLM 호출 9회, $0.136, 89초였습니다. 첫 화면 카드는 이 Claude 기록을 엽니다.

### 4.2 사례 B: 1차 긴급재난지원금 (2020-05) → 판정 보류

- **설계.** 사전 등록 문서(`docs/prereg/case_relief2020_engine.md`)를 그대로 썼습니다. 대상은 도민 × 사용 가능 업종 24개, 대조는 도민 × 사용 불가 업종이고, 법인은 공간 위약으로 썼습니다.
- **결과.** 사용 기간(5~8월) 평균 −4.9%(판정 구간 −17.0% ~ +9.0%)입니다. 구분 가능한 최소 효과가 ±16.0%라 기준 효과 10%를 가릴 수 없습니다(검정력 부족). 효과가 유의하지 않아 시점 위약검정(C2a, 순위 p=0.317)은 참고로만 봅니다.
- **해석.** 5월만 따로 보면 +3.0%로 KDI 연구와 방향이 같습니다. 그러나 이 창은 결과를 본 뒤 고른 것이라 근거로 쓰지 않습니다. 월 단위·단일 카드사 자료로는 확정할 수 없습니다. 첫 분석의 판정 후보였던 '조건부'는 사전 등록한 엔진 재판정으로 '보류'가 되었습니다.
- **Claude 실행.** 반론 2개(사후 기간을 2개월로, 대조를 대형 종합 소매로)를 스스로 세워 다시 추정했습니다. 둘 다 유의하지 않아 '해당 없음'이고 판정은 같은 '보류'입니다.
- **다시 판정할 때.** 끝난 정책이라 기다려도 관측이 늘지 않습니다. 일 단위나 전체 카드사 자료가 필요합니다.

### 4.3 사례 D: 중국 단체관광 재개 (2023-08-10) → 판정 보류

- **설계.** 사전 등록 문서(수정 1)를 썼습니다. 업종 패널 이중차분이고, 대조는 일본·동남아·기타외국입니다. 2019년 같은 달 기준이고, 업종 × 월 고정효과를 넣었습니다.
- **결과.** 주분석 +170.9%였지만 사전추세 검정이 크게 깨졌습니다(p=9.9×10⁻⁷). 민감도(C3)도 실패했습니다.
- **해석.** 중국인 소비는 정책 전부터 회복하고 있었고, 정책 시점에 뚜렷한 단절이 보이지 않습니다. 다만 정책 전 시점이 3개뿐이라 사전추세 검정도, 추세를 직선으로 연장한 보정 추정(−75.8%)도 불안정합니다. 그래서 "정책 효과가 없다"가 아니라 "이 자료로는 회복 추세와 정책 효과를 가를 수 없다"로 읽습니다. 개정안 v3는 같은 사례를 '정책 전 시점 부족'으로 보류합니다.
- **데이터 문제.** 2023-05~06 외국인 4개 집단 결측을 자동으로 찾았습니다.
- **판정 기록(사후 변경 공개).** 사전 등록 당시 규칙 v1으로는 원 등록 분석이 '판정 보류', 이 판정서가 따르는 수정 1 분석(외국인 결측 대응, 값을 보기 전에 결정)이 '조건부(증가)'였습니다. 지금의 공식 규칙 v2.0(사전추세가 크게 깨지면 상한 '보류')은 **이 사례 결과를 본 뒤** 보완한 것입니다. 그래서 v1 판정을 판정서에 함께 적습니다. 규칙 변경 이력은 코드(`RULE_HISTORY`)에 날짜와 함께 남겼습니다.
- **반론 판정 규칙 보완(11-09).** 외부 검토에서 크루즈 재입항 기간을 빼고 다시 추정한 반론이 효과가 오히려 커졌는데(+181%) '성립'으로 표시되는 문제를 찾았습니다. 이제는 점추정이 절반 넘게 줄거나 방향이 바뀔 때만 '성립'이고, 크기는 유지된 채 유의성만 사라지면 '판단 불가(검정력 부족)'입니다. 크루즈 재입항은 사전 등록에서 추정 대상에 포함한 사건이라 반론으로 쓰지 않습니다. 판정은 바뀌지 않았습니다.
- **Claude 실행.** 반론 3개를 스스로 세웠습니다. 비자 중단 기간(2023-01~02)을 빼도 +170.9%로 같아 '기각', 사후 3개월만 보거나 일본만 비교하면 크기는 유지(+151%, +80%)됐지만 유의하지 않아 '판단 불가'입니다. 판정은 같은 '보류'입니다.

### 4.4 사례 E: 사회적 거리두기 전면 해제 (2022-04-18) → 판정 보류 (양성 대조)

- **왜 했나.** 실데이터에서 '효과 있음'이 한 번도 나오지 않아서, 효과가 있다고 널리 알려진 정책을 일부러 골랐습니다.
- **사전 등록.** `docs/prereg/case_distancing_2022.md`, 2026-11-06 00:30 잠금. 결과를 본 뒤 설계는 바꾸지 않았습니다.
- **설계.** 제주도민 × 주점(일반유흥·기타 주점)을 식료품 소매 5업종과 비교했습니다. 사전 12개월, 사후 6개월입니다. 과거 같은 달도 방역 기간이라 계절 차분은 쓰지 않았고, 가짜 시행일은 방역 기간 밖에서만 뽑았습니다.
- **결과.** 추정 +201.2%였고 실패한 검증은 없습니다. 주분석이 유의하지 않아 시점 위약(가짜 34개 중 순위 p=0.029)과 민감도는 참고로만 봅니다. 판정 구간이 −66.2% ~ +2586.4%로 넓어 규칙상 '보류'입니다. 사전 등록에서 정한 대로 **"양성 대조에서 효과를 확인하지 못함"**으로 보고합니다.
- **원인.** 기준 기간 안의 2021-08(거리두기 4단계 무렵)에 주점 결제가 거의 사라졌습니다. 대상/대조 로그 격차로 보면 사전 중앙값보다 4.44 낮습니다. 이 한 달이 기준선과 분산을 함께 흔들었습니다.
- **판정서의 설명.** "사후 5524개월 필요" 같은 엉뚱한 안내 대신 "기준 기간의 이상 시점(2021-08)을 먼저 확인"이라고 쓰도록 보강했습니다.
- **보조 확인(사전 등록 밖, 판정에 쓰지 않음).** 다른 파일(시간대별 카드 이용 금액)에서 도민 소비 중 밤 시간대 비중을 봤습니다.

  | 시점 | 밤 비중 |
  |---|---|
  | 2019년(코로나 전) | 11.5% |
  | 해제 직전 | 4.4% |
  | 해제 뒤 | 9.6% |

  늦은 시간 소비가 해제 뒤 두 배 넘게 회복했습니다. 이 확인은 사전 등록 밖의 서술 통계라 판정 근거가 아닙니다. E의 '보류'는 효과가 없다는 뜻이 아니라, 기준 기간이 흔들려 이 설계로는 확정할 수 없다는 뜻입니다. 실데이터에서 '효과 있음'을 낸 사례는 아직 없고, 이 점을 그대로 보고합니다.
- **반론 재계산 수치 오류 수정(11-09).** 오미크론 감소기를 빼고 다시 추정한 반론 수치가 +1496.3%로 찍혀 있었습니다. 반론 재계산 함수가 잠긴 설계의 '계절 차분 없음' 설정을 넘기지 않은 버그였고, 고친 뒤 +200.6%입니다. 판정은 바뀌지 않았습니다.

### 4.5 사례 C: 합성데이터 (정답 +22.1%) → 효과 있음(증가)

### 4.6 사례 F: 합성데이터 2 (정책 효과 0, 같은 시기 행사) → 판정 보류(Skeptic 하향)

- **데이터.** 합성 버스 데이터에 2024-09-02 '청소년 야간 버스 증편'을 시행일로 두되 정책 효과는 0으로 두었습니다. 대신 2024-09-16~11-24 청소년 대상 행사가 이용을 +49% 늘리게 했고, 이 행사를 사건 달력에 올려 두었습니다.

- **Claude 실행.** Claude Skeptic은 반론 4개를 스스로 세웠습니다. 행사 기간 제외(−2.7%, 성립), 사후 60일만 보기(+30.8%, 기각), 대조를 경로 승객으로 바꾸기(+15.4%, 기각), 사전 추세·계절(규칙 검증으로 기각)입니다. 성립한 하나로 '효과 있음'을 '판정 보류'로 낮췄습니다. LLM 호출 10회, $0.124, 54초.
- **의미.** 검증 항목을 모두 통과해도 같은 시기 다른 사건은 판정 규칙이 보지 못합니다. 이 사례는 반론 단계가 실제로 판정을 바꾸는 장면입니다. 규칙 v3(개정안)도 규칙 결과는 같은 '효과 있음'이고, 반론 하향은 두 규칙에 똑같이 적용됩니다.

### 5.1.1 판정 규칙 v3(개정안)와 나란히

외부 검토에서 나온 지적(동등성 방식의 '효과 없음', 정책 전 시점 4개 미만 보류, 위약검정 표본 수·체제 점검, 패널 사전추세 검정)을 반영한 v3로 같은 2,400회를 다시 판정했습니다. 공식 판정은 사전에 정한 v2이고, 판정서에는 두 판정을 나란히 보여 줍니다.

| 지표 | v2(공식) | v3(개정안) |
|---|---|---|
| 이상적 판정 | 72.4% | 72.7% |
| 효과 없는데 '효과 있음' | 2.4% | 2.4% |
| 효과 있는데 '효과 없음' | 0.1% | 0.0% |
| 실제 효과에 '효과 있음'(시계열/패널) | 83.0% / 74.5% | 84.0% / 74.5% |
| 판정 보류 비율 | 37.6% | 37.6% |
| '효과 있음' 판정의 적중률 | 95.4% | 95.5% |
| '조건부' 판정의 적중률 | 50.4% | 49.9% |

'조건부'는 절반만 실제 효과가 있었으므로 성과 근거로 단독 인용하지 않도록 판정서에 적습니다. 적중률은 시나리오 구성에 따라 달라지므로 현장 적중률로 읽지 않습니다. 실데이터 4건과 시연 2건은 v2·v3 판정이 모두 같고, B·D는 v3에서 보류 이유가 '정책 전 시점 부족'으로 바뀝니다.

- **보강한 문제.**
  - 같은 PC에서도 앞서 실행한 작업에 따라 부동소수 마지막 비트가 달라졌습니다 → 정규화 지문으로 해결
  - 사례를 하나 추가하자 기존 Claude 기록의 프롬프트가 바뀌었습니다 → 참고 사례 목록 고정으로 해결
  - 사건 달력이 늘어나 기존 기록과 어긋났습니다 → 원래 실행 날짜의 달력을 쓰게 해 해결
- **설치 점검(Windows 실제 PC, 11-08).** Windows 11 PC에서 압축을 풀고 `점검.bat`을 실행했습니다.
  - 첫 묶음은 실패 6건이었습니다. Mac에서 내려받은 카드 데이터 파일 이름이 자모 분리형(NFD)으로 들어가, Windows에서는 다른 이름으로 보였기 때문입니다.
  - Mac에서 흉내 낸 점검은 Mac이 두 이름을 같게 보기 때문에 이 문제를 잡지 못했습니다.
  - 묶음의 모든 파일 이름을 완성형(NFC)으로 바꾸고, 아니면 묶음 만들기가 멈추도록 고쳤습니다. 다시 만든 묶음은 같은 PC에서 실패 0건이었습니다.
  - 화면·실데이터 시험 10개 항목을 모두 통과했습니다: 실행 화면, 진행 재생, PDF 1쪽, 합성 사례 판정 시작, 정답 +19.6%, 요약 복사, 재실행 재현, 실데이터 판정, 공문 초안, 직접 만들기.
  - 실데이터 사례 1건(청소년 버스 무료화)은 질문에서 판정서까지 22.9초가 걸렸습니다.

### 5.3 한계

| 한계 | 대응 |
|---|---|
| 실데이터 4건 모두 '보류', '효과 있음' 실데이터 사례 없음 | 결과에 맞춰 설계를 바꾸지 않음. '효과 있음'의 작동은 합성데이터로 검증 |
| 합성데이터 정확도는 낙관적일 수 있음 | 잡음 크기는 실데이터에 맞췄지만, E의 2021-08 같은 이상 시점이나 구조 변화까지 흉내 내지는 못함. 실데이터 기반 시험은 앞으로의 과제 |
| 반론(Skeptic) 단계의 성능은 따로 측정하지 않음 | 하향 사례는 합성 F 1건. 정확도 2,400회는 판정 규칙만 잰 값 |
| 패널 설계는 구조상 '효과 없음'을 내기 어려움 | 합성 '패널: 아무 일도 없음'에서 이상적 판정 0%(대부분 보류). 판정서에 검정력과 함께 표기 |
| 공개 데이터의 해상도(월 단위·단일 카드사)가 낮아 검정력 부족 | 구분 가능한 최소 효과를 함께 보고. 센터 일 단위 자료 연계를 확장 계획에 둠 |
| 측정 단절·결측의 원인을 데이터만으로 확인할 수 없음 | '의심'으로 표기하고 제공처 확인 방법을 판정서·품질 점검 보고에 적음 |
| 평행추세 등 인과 가정은 검정으로 완전히 증명할 수 없음 | 판정서마다 '이 분석이 말할 수 없는 것' 문단 |
| 사례 B의 비교군 교체는 데이터를 본 뒤의 결정 | 사후 결정임을 명시하고, 엔진 재판정은 설계를 먼저 잠근 뒤 실행(열람 사실 고지) |
| 오프라인 모드는 문장으로 된 새 질문을 해석하지 못함 | 정책 카드 직접 만들기로 새 정책을 판정 |
| 공개 웹 데모에는 실데이터 없음 | 허브 재배포 조건 미확인. 기록된 판정서와 합성데이터 판정만, 실데이터는 설치 묶음 |

## 6. 센터 활용 방안

### 6.1 바로 쓸 수 있는 것

1. **정책 판정 서비스.** 부서가 질문이나 정책 카드를 보내면 센터가 판정서를 발행합니다. 보류이면 자료 요청 공문 초안과 다시 판정할 시점을 함께 돌려줍니다. 판정마다 잠긴 설계와 재실행 기록이 남습니다. 그래서 감사·검증 때 "같은 판정 다시 만들기"가 됩니다.
2. **공개 데이터 품질 감시.** 새 데이터를 올릴 때 같은 품질 점검(`jverdict.quality`)을 돌리면, 집계 방식이 바뀐 날을 공개 전에 찾을 수 있습니다. 이번에 찾은 5건은 「허브 데이터 품질 점검 보고」로 별첨했습니다.
   - 청소년 무료화 시점의 측정 단절
   - 2025-01 '기타' 신설
   - 104일 결측
   - 부분 집계 126일
   - 외국인 2개월 결측
3. **연구용역 사전 설계.** 사전 등록 문서를 과업 산출물로 요구하고, 필요한 비교 집단·기간을 과업지시서에 미리 넣습니다.

### 6.2 확장

| 확장 | 내용 |
|---|---|
| 센터 내부 데이터 연계 | 일 단위 쓰레기·날씨·카드 전체 자료로 검정력 향상. 예: 재활용품 요일별 배출제(2027 존폐 결정)·상시배출 시범의 사전 평가 설계 |
| 추정 방법 | 합성통제, 회귀불연속, 집단별(연령·지역) 이질적 효과 |
| 지역 단위 | 정류소 → 읍면동 매핑(정류소 API 확보 완료)으로 지역 정책 판정 |
| 운영 | 판정 이력 관리, 부서별 요청·공유, 재판정 알림 |
