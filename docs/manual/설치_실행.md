# 정책 판정관 설치·실행 안내 (Windows)

이 안내는 `JVerdict_win64_<날짜>.zip`(실행 환경 포함 묶음) 기준입니다. 이 묶음에는 Python과 필요한 패키지가 모두 들어 있습니다.
**인터넷, 따로 설치하는 프로그램, 관리자 권한은 모두 필요 없습니다.**

| 항목 | 필요 조건 |
|---|---|
| 운영체제 | Windows 10 또는 11, 64비트 |
| 디스크 | 압축 파일 약 220MB와 푼 뒤 약 560MB. 판정 기록이 쌓일 여유를 더해 **1GB 정도** |
| 브라우저 | Chrome 또는 Edge. 화면을 열고 1장 판정서 PDF를 인쇄할 때 씁니다. Edge는 Windows에 기본으로 들어 있습니다 |
| 인터넷 | 필요 없음. Claude 모드를 쓸 때만 필요합니다(5장) |

---

## 1. 압축 풀기

1. **(인터넷에서 받은 경우) 차단 해제를 먼저 합니다.** 압축 파일을 오른쪽 클릭하고 **속성**을 엽니다. 아래쪽 **차단 해제**에 체크한 뒤 **확인**을 누릅니다.
   이렇게 하면 실행할 때 나오는 Windows 보안 경고가 줄어듭니다.
2. **짧은 경로에 풉니다.** 예: `C:\JVerdict`, `D:\JVerdict`
   - Windows는 파일 경로가 260자를 넘으면 파일을 열지 못합니다. 묶음 안에서 가장 긴 경로가 150자 정도이므로, 압축을 푸는 위치의 경로는 **100자 이내**여야 합니다.
     `C:\Users\<이름>\Downloads\` 정도는 괜찮습니다.
   - `C:\Program Files` 아래에는 풀지 마세요. 판정 기록을 저장할 수 없습니다.
3. 반디집, 7-Zip, Windows 기본 압축 풀기 가운데 무엇이든 쓸 수 있습니다.
   **한글 파일 이름이 깨져 보이면** 다른 프로그램으로 다시 풀어 주세요. 반디집이나 7-Zip을 권장합니다.

압축을 풀면 다음과 같이 보입니다.

```
JVerdict\
  실행.bat        ← 화면 열기
  점검.bat        ← 설치 점검
  설치.bat        ← (실행 환경이 없는 묶음일 때만 사용)
  README.md
  runtime\        ← Python 3.14.3과 패키지(건드리지 않음)
  src\  data\  outputs\  docs\  tests\ ...
```

## 2. 설치 점검: `점검.bat`

`점검.bat`을 두 번 클릭합니다. 1~2분 동안 아래 항목을 확인한 뒤 결과를 보여 줍니다.

| 구분 | 확인하는 것 |
|---|---|
| 환경 | Python 버전, 파일 경로 길이, 결과 폴더 쓰기 권한, 한글 입출력 |
| 패키지 | 설치된 패키지 버전이 판정 기록을 만든 환경과 같은지(`requirements/lock-win-cp314.txt`) |
| 묶음 무결성 | 묶음의 모든 파일이 빠짐없이 풀렸는지(`SHA256SUMS.txt`). 한글 이름이 깨졌다면 여기서 드러납니다 |
| 데이터 | 데이터셋마다 데이터 지문이 원래 판정 때와 같은지 |
| 판정 재현 | 사례 A·B·C·D를 이 PC에서 **새로 판정**했을 때 제출본 기록과 수치·판정이 같은지, Claude 실행 기록을 **API 없이** 다시 돌렸을 때 같은 판정서가 나오는지 |
| 판정서·화면 | 1장 판정서 PDF 인쇄, 화면 첫 페이지 |
| 보안 | API 키는 설정 여부만 표시, 화면이 이 PC 안에서만 열리는지 |

- 결과는 `통과 · 주의 · 실패 · 정보`로 나옵니다. **실패가 0개면 사용할 수 있습니다.**
- 보고서는 `outputs\doctor\점검_<날짜-시각>.txt`에 남습니다. 보고서에는 설치 폴더 경로가 `<설치 폴더>`로, 홈 폴더가 `~`로 가려져 들어가고 비밀값은 들어가지 않으므로 그대로 공유해도 됩니다.
- 묶음 파일 전체의 SHA-256까지 대조하려면 명령 창에서 `점검.bat --full`을 실행합니다. 몇 분 걸립니다.
- 처음 실행할 때는 Python이 패키지를 준비하느라 더 오래 걸립니다. 두 번째부터는 빨라집니다.

## 3. 화면 열기: `실행.bat`

`실행.bat`을 두 번 클릭하면 검은 명령 창이 뜨고, 잠시 뒤 브라우저에 화면이 열립니다.

- 화면 주소는 `http://localhost:8501`입니다. 브라우저가 저절로 열리지 않으면 명령 창에 나온 주소를 브라우저에 직접 넣으세요.
- 화면은 **이 PC 안에서만** 열립니다. 같은 네트워크의 다른 PC에서는 접속할 수 없고, 사용 통계도 밖으로 보내지 않습니다.
- 끝낼 때는 명령 창에서 `Ctrl+C`를 누르거나 명령 창을 닫습니다.
- 화면을 이미 하나 열어 둔 상태라 8501 포트를 쓰고 있으면, 다음 빈 포트(8502 등)로 열고 그 주소를 알려 줍니다.

### 화면 사용 순서
1. **질문을 입력합니다.** 예시 버튼 네 개(사례 A·B·D·C) 가운데 하나를 눌러도 됩니다.
2. **정책 카드를 확인합니다.** Agent가 질문을 정책·시행일·대상·결과지표로 정리한 카드를 보여 주고 승인을 기다립니다. 기대하는 방향과 '의미 있다고 볼 최소 효과'는 고칠 수 있습니다.
3. **진행 상황을 봅니다.** 데이터 점검 → 설계 잠금 → 추정 → 반론 검증 → 판정서 순서로 진행됩니다.
4. **판정서를 읽습니다.** 판정 등급과 그 뜻, 그래프, 검증표, 반론표, 한계, 판정에 필요한 데이터가 나옵니다.
5. **재현과 내려받기.** `재현·내려받기` 탭에서 버튼 하나로 같은 판정을 다시 만들어 대조할 수 있고, 1장 판정서 PDF를 내려받을 수 있습니다.

왼쪽 메뉴의 **정확도 리포트**에서는 정답을 아는 합성데이터 2,400회로 잰 판정 정확도를 볼 수 있습니다.

## 4. 판정 기록과 판정서

- 실행할 때마다 `outputs\runs\<실행 번호>\`가 생깁니다. 판정서 원문(`report.md`), 1장 판정서(`verdict.pdf`), 잠근 설계 문서(`prereg.md`), 재실행 기록(`manifest.json`)이 들어 있습니다.
- 제출본에 들어 있는 사례 기록은 `case-<사례>-<모드>` 폴더이며, 요약표는 `outputs\runs\_summary.md`에 있습니다.

## 5. Claude 모드 (선택)

키가 없으면 **템플릿 모드**로 판정합니다. 판정 규칙과 수치는 두 모드에서 같습니다. Claude 모드는 질문 해석, 설계, 반론, 판정서 문장을 Claude가 맡습니다.

1. `.env.example` 파일을 복사해 이름을 `.env`로 바꿉니다.
   메모장으로 저장할 때 파일 형식을 **모든 파일**로 고르세요. 그렇지 않으면 `.env.txt`가 됩니다.
2. `ANTHROPIC_API_KEY=` 뒤에 키를 붙여 넣고 저장합니다.
3. `실행.bat`을 다시 실행하고, 왼쪽 메뉴에서 실행 방식을 **Claude**로 고릅니다.

- 인터넷이 필요하고, 판정 1건에 약 $0.1이 듭니다.
- 키 값은 화면, 보고서, 판정 기록, 오류 메시지 어디에도 나오지 않습니다. 화면에는 '설정됨/없음'만 보입니다.
- Claude에는 집계된 통계만 보내고, 원자료는 보내지 않습니다.
- 인터넷이 끊기거나 키에 문제가 있으면 그 단계부터 템플릿 모드로 바꿔 판정을 끝까지 마칩니다. 진행 기록에 그 사실이 남습니다.

## 6. 명령줄 (선택)

설치 폴더에서 명령 창을 열고 다음과 같이 실행합니다.

```bat
runtime\python.exe -m jverdict.agent --case A --yes                       :: 사례 A 판정(템플릿)
runtime\python.exe -m jverdict.agent --replay outputs\runs\case-A-claude  :: 같은 조건 재실행·대조
runtime\python.exe -m jverdict.report --all                               :: 모든 기록의 1장 판정서 다시 만들기
runtime\python.exe -m pytest -q                                           :: 자동 시험
```

## 7. 문제 해결

| 증상 | 해결 |
|---|---|
| 보안 경고 창이 뜸("Windows의 PC 보호" 또는 "열기 - 보안 경고") | 파란 창이면 **추가 정보 → 실행**을, 경고 창이면 **실행**을 누릅니다. 1장의 '차단 해제'를 하고 다시 풀면 뜨지 않습니다 |
| 백신이 `python.exe`를 막음 | `runtime\python.exe`는 python.org 공식 파일입니다(SHA-256을 대조해 넣음). 백신에서 이 폴더를 허용해 주세요 |
| 점검 결과 '파일 목록 대조' 실패, 한글 이름이 깨짐 | 반디집이나 7-Zip으로 다시 풉니다 |
| 점검 결과 '파일 경로 길이' 실패 | `C:\JVerdict`처럼 짧은 경로로 폴더를 옮깁니다 |
| 점검 결과 '결과 폴더 쓰기 권한' 실패 | `Program Files`나 읽기 전용 위치를 피해 내 문서나 `C:\JVerdict`로 옮깁니다 |
| 브라우저가 열리지 않음 | 명령 창에 나온 `http://localhost:8501` 주소를 직접 엽니다 |
| PDF가 아니라 HTML 판정서만 만들어짐 | Chrome·Edge를 찾지 못한 경우입니다. HTML을 브라우저에서 열어 인쇄해도 같은 판정서가 나옵니다. 브라우저가 특이한 위치에 있으면 환경변수 `JVERDICT_BROWSER`에 그 실행 파일 경로를 넣습니다 |
| 처음 실행이 느림 | 첫 실행 때만 패키지를 준비합니다. 두 번째부터 빨라집니다 |
| 그 밖의 오류 | `점검.bat`을 실행하고 `outputs\doctor\` 안의 보고서 파일을 보내 주세요 |

## 8. 실행 환경이 없는 묶음 (`JVerdict_src_*.zip`)

Python 3.11 이상이 이미 설치된 PC용입니다. `설치.bat`을 실행하면 다음 순서로 진행합니다.
1. `.venv`(가상환경)를 만듭니다.
2. 고정 버전 패키지(`requirements/lock-win-cp314.txt`)를 내려받습니다. 인터넷이 필요합니다.
   고정 버전을 설치할 수 없는 Python이면 호환 버전(`requirements/base.txt`)을 대신 설치하는데, 이때는 판정 수치가 마지막 자리에서 다를 수 있습니다.
3. 설치가 끝나면 설치 점검을 실행합니다. 그다음부터는 `실행.bat`으로 화면을 엽니다.

## 9. 묶음 만들기 (개발 PC)

```bash
.venv/bin/python tools/build_bundle.py          # dist/JVerdict/ 와 dist/JVerdict_win64_<날짜>.zip
.venv/bin/python tools/build_bundle.py --no-runtime   # 실행 환경 없는 묶음(JVerdict_src_*.zip)
```

빌드 도구는 다음 과정을 거칩니다. 검사에 하나라도 실패하면 압축하지 않습니다.
1. python.org 공식 임베디드 Python을 받아 SHA-256을 대조합니다.
2. 개발 PC와 같은 버전의 Windows용 패키지를 미리 풀어 넣습니다. Windows에서만 필요한 의존성(`colorama`, `watchdog`)도 따로 찾아 넣습니다.
3. 다음 검사를 합니다.
   - Windows용이 아닌 바이너리가 섞이지 않았는지
   - `.env` 파일이 없는지
   - 실제 키 값이 0건인지, 키 모양 문자열이 0건인지
   - 배치 파일이 CRLF인지
   - 경로 길이가 한도 안인지
4. 검사를 통과하면 압축하고 CRC를 검사합니다.
5. 압축을 새 폴더에 풀어 원본 CSV가 없는 상태에서 점검을 끝까지 돌립니다.

1GB가 넘는 버스 원본 CSV는 싣지 않습니다. 대신 가공 파일(`data/processed/*.parquet`)을 싣고, 원본 지문은 `data/processed/_sources.json`으로 확인합니다. 이 기록에는 원본 CSV의 지문과 그 원본에서 만든 가공 파일의 지문이 짝으로 적혀 있습니다. 가공 파일이 바뀌면 이 확인에서 오류로 멈춥니다.
