# 정책 판정관 J-Verdict 사용자 매뉴얼

### 질문 하나로 정책 효과 판정서를 받는 방법

대상: 도청·센터 실무자(통계 지식이 없어도 됩니다) · 버전 2026-11-07 · 설치는 [설치_실행.md](설치_실행.md)

---

## 1. 이 프로그램이 하는 일

"청소년 버스 무료화, 효과 있었어?" 같은 질문을 받으면, Agent가 다음 순서로 스스로 분석해 **1장짜리 판정서**를 냅니다.

**데이터 점검 → 비교 설계(잠금) → 추정 → 반론 검증 → 판정서**

| 판정 | 뜻 |
|---|---|
| 🟢 효과 있음 | 정책 이후의 변화가 우연·계절·기존 추세·측정 방식 변경으로 설명되지 않는지 확인하는 검증을 모두 통과했습니다 |
| 🟡 조건부 | 변화의 방향은 보이지만 검증 일부를 통과하지 못했거나 신호가 약합니다. 성과 근거로 단독 인용하지 마세요(합성 시험에서 조건부의 절반만 실제 효과) |
| ⚪ 효과 없음 | 의미 있는 크기의 변화가 있었다면 잡아낼 수 있을 만큼 자료가 충분했지만, 그런 변화가 보이지 않았습니다 |
| 🟣 판정 보류 | 현재 자료로는 효과가 있다고도 없다고도 말할 수 없어 결론을 미룹니다. **실패 판정이 아닙니다.** 필요한 자료를 확보하면 다시 판정할 수 있습니다. 화면에서는 남보라 점선 도장으로 표시합니다 |

판정관은 **틀린 결론을 내지 않는 것**을 가장 중요하게 봅니다. 근거가 부족하면 '판정 보류'라고 답합니다. 대신 왜 결론을 낼 수 없는지와 무엇이 있으면 낼 수 있는지를 함께 알려 줍니다.

## 2. 시작하기

1. `실행.bat`을 두 번 누르면 브라우저에 첫 화면이 열립니다. 주소는 `http://localhost:8501`이고, 이 PC 안에서만 열립니다.
2. 실행 방식은 왼쪽 메뉴 맨 아래 **실행 설정**에서 고릅니다.
   - **기본(오프라인)**: 기본값입니다. 인터넷과 API 키가 필요 없습니다.
   - **Claude 판단**: 각 단계의 판단을 Claude가 합니다. 원자료 행이 아니라 집계 통계만 보냅니다. `.env`에 API 키가 있어야 하고, 실행 1건에 약 $0.1이 듭니다. 판정 규칙과 수치 계산은 두 방식이 같습니다.
3. 설치 없이 둘러보려면 웹 데모 https://jverdict.streamlit.app 을 쓰세요. 웹 데모에는 허브 원자료가 없습니다. 그래서 실데이터 사례는 기록된 판정서를 열고, 합성데이터만 그 자리에서 판정합니다.

<!-- img: images/s01_start.jpg 첫 화면: 실제 정책 4건의 '단순 비교였다면 → 판정관' 카드, 질문으로 시작 / 직접 만들기 두 탭 -->

첫 화면 맨 위 카드 네 장은 실제 제주 정책 4건의 결과입니다. **▶ 진행 재생 · 판정서**를 누르면 Agent가 단계를 밟은 기록을 몇 초 동안 다시 보여 준 뒤 판정서를 엽니다(다시 계산하지 않음).

## 3. 질문으로 판정하기

1. **예시 질문**을 누르거나 질문 칸에 직접 적습니다. 예시는 여섯 가지입니다.

   | 예시 | 내용 |
   |---|---|
   | 청소년 버스 무료화 | 사례 A |
   | 1차 재난지원금 | 사례 B |
   | 중국 단체관광 재개 | 사례 D |
   | 거리두기 전면 해제 | 사례 E |
   | 정답 있는 합성데이터 | 시연 C |
   | Skeptic 반론 | 시연 F: 같은 시기 행사를 정책 효과로 착각하지 않는지 |

2. **판정 시작**을 누릅니다.
3. **② 정책 카드 확인**: Agent가 질문을 정책 카드(무엇을 · 언제부터 · 누구에게)로 바꿉니다.
   - 확인하고 필요하면 고칠 수 있는 것은 기대하는 변화 방향과 '의미 있다고 볼 최소 효과'입니다.
   - ⚠️ 표시는 Agent가 세운 가정 중 확인이 필요한 것입니다.
   - **이 카드로 판정 시작**을 누르면 비교 설계가 잠깁니다. 잠근 뒤에는 결과를 보고 설계를 바꿀 수 없습니다.

<!-- img: images/s02_card.jpg 정책 카드 확인: 사람이 한 번 확인하면 설계를 잠그고 분석을 시작합니다 -->

4. 진행 화면에서 단계 표시와 진행 기록이 쌓입니다. 오프라인 모드는 보통 수 초에서 20초, Claude 모드는 40~70초 걸립니다.
5. 기본(오프라인) 모드에서 문장으로 된 새 질문은 해석하지 못합니다. 새 정책은 **직접 만들기** 탭을 쓰거나, 실행 설정에서 Claude 판단을 켜세요.

## 4. 직접 만들기 (새 정책, API 키 없이)

등록 사례가 아닌 정책도 아래 여섯 가지만 고르면 판정합니다.

| 칸 | 고르는 것 | 메모 |
|---|---|---|
| ① 데이터 | 분석할 데이터셋 | 기간과 단위(일·월)가 아래에 표시됨 |
| ② 정책 이름 | 판정서 제목 | 예: 청소년 요금 할인 |
| ③ 시행일 | 정책 전 비교 기간과 정책 후 자료가 모두 있는 날짜 | 월 단위 자료는 그 달 1일로 맞춤 |
| ④ 정책 대상 | 이용자 유형(버스) 또는 이용자 구분(카드). 카드는 업종도 고를 수 있음 | 업종을 비우면 전체 |
| ⑤ 비교 대상 | **Agent가 고르기**(권장) 또는 **직접 고르기** | Agent가 고르면 정책 대상이 아닌 집단 가운데 정책 전 움직임이 가장 비슷한 집단을 효과 값을 보지 않고 고름 |
| ⑥ 기대하는 변화 | 늘었는가 / 줄었는가 / 정하지 않음 | 의미 있다고 볼 최소 효과(%)도 함께 |

<!-- img: images/s13_builder.jpg 정책 카드 직접 만들기: 목록에서 고르면 됩니다 -->

**이 카드로 판정 시작**을 누르면 정책 카드 확인 화면이 나옵니다. 여기서 '비교 설정'에 대상과 대조 후보가 보입니다. 이후 과정은 등록 사례와 같습니다.

## 5. 판정서 읽는 법

<!-- img: images/s04_verdictA_top.jpg 판정서 맨 위: 판결문식 머리, 판정 도장과 요지·원인·검증·다음, 숫자 띠 -->

| 위치 | 읽는 법 |
|---|---|
| 머리 | 문서번호·판정일, 정책 이름, 질문, 사건 정보(시행일·대상·자료), 판정 방식(오프라인/Claude, 판정 규칙, 설계 잠금 지문). 오른쪽 위 **1장 판정서 PDF** |
| 판정 도장 | 효과 있음(이중선) · 조건부(실선) · 효과 없음 · 판정 보류(점선). 아래 작은 글씨는 보류 이유(측정 단절 의심, 자료 부족, 기존 추세와 구분 불가, 기준 기간 이상, 같은 시기 다른 사건) |
| **요지** | 보류여도 지금 말할 수 있는 것. 예: "공개 자료의 −76% 변화는 정책 효과(또는 실패)의 근거로 쓸 수 없음" |
| 원인·검증·반론·다음 | 결론의 이유, 검증 통과·실패·참고 개수, Skeptic 하향 여부, 다음에 할 일 |
| 규칙 v3(개정안) | 같은 결과를 개정 규칙으로 다시 판정한 값. 공식 판정은 사전에 정한 v2 |
| 숫자 띠 | **단순 전후 비교였다면** → 판정관 추정(보류면 '참고치') → 구분 가능한 최소 변화 → 가짜 시행일 시험. 맨 아래 한 문장이 두 결론이 왜 다른지 설명합니다 |
| 그래프 | 대상과 대조 집단의 차이. 0% 선은 '정책이 없었다면'의 기준, 굵은 선은 정책 후 평균, 띠는 판정 구간 |

판정서 아래 탭은 다음과 같습니다.

| 탭 | 내용 |
|---|---|
| **다음 할 일** | 다시 판정할 때(기간으로 풀리는지, 자료가 필요한지), 결재 보고서에 붙일 개조식 요약(복사), 자료 요청 공문 초안(행정 공문 서식, 내려받기), 판정에 필요한 데이터, 이 분석이 말할 수 없는 것, 한계, 판정 문장 전문 |
| 검증·반론 | C0 데이터 품질 · C1 사전추세 · C2a 가짜 시행일 시험 · C2b 가짜 대상 시험 · C3 민감도 · C4 이중 계산, 반론과 검증 결과, 규칙 v2·v3 비교 |
| **Agent의 판단** | 단계마다 누가(Claude·규칙·사용자) 무엇을 왜 정했는지와 부른 툴. Claude 실행은 같은 사례의 오프라인 실행과 비교표로. **▶ 진행 과정 다시 재생**, 원문 로그 |
| 설계 문서(잠금) | 효과를 보기 전에 잠근 설계와 지문(SHA-256)·시각 |
| 재현·내려받기 | 지금 다시 실행해 같은 결과인지 대조, 1장 판정서 PDF·HTML·원문 내려받기 |

## 6. 재현과 내려받기

**지금 재실행해서 확인**을 누르면 같은 기록으로 처음부터 다시 실행해 아래 항목이 같은지 비교합니다.

- 핵심 수치
- 판정
- 판정서 문장
- 데이터 지문
- 코드 지문

Claude 실행도 API를 부르지 않고 저장된 응답 기록으로 다시 실행합니다. **1장 판정서 PDF**는 결재 문서에 그대로 붙일 수 있습니다. PDF를 만들려면 PC에 Chrome 또는 Edge가 있어야 하고, 없으면 HTML로 저장됩니다.

## 7. 그 밖의 화면

- **＋ 새 판정**(왼쪽 메뉴 맨 위): 처음 화면으로 돌아갑니다.
- **지난 판정서**(왼쪽 메뉴): 판정 · 정책명 · 실행 방식 목록에서 고르면 바로 열립니다.
- **정확도 리포트(합성데이터)**: 정답을 심어 둔 합성데이터로 잰 정확도입니다. 인과 판정 2,400회에서 실제 효과에 '효과 있음'을 낸 비율은 83%(시계열)·74.5%(패널), 없는 효과를 '효과 있음'이라 한 비율은 2.4%, 판정 보류는 37.6%입니다.
- **판정 등급의 뜻**(왼쪽 메뉴): 위 1장의 표와 같습니다.

## 8. 오류와 제약

| 상황 | 원인과 대처 |
|---|---|
| "등록된 정책 카드와 맞는 질문이 아님" | 오프라인 모드는 등록 사례의 질문만 해석합니다. **정책 카드 직접 만들기**를 쓰거나, API 키를 넣고 Claude 모드를 고르세요 |
| "Claude API 키가 설정되지 않아 오프라인으로 실행합니다" | `.env`에 키가 없습니다. 판정은 오프라인으로 그대로 진행됩니다 |
| Claude 단계가 실패함(크레딧 소진·네트워크) | 그 단계만 오프라인(템플릿)으로 자동 대체하고, 진행 기록과 판정서에 '템플릿 대체'로 남깁니다 |
| 시행일을 고를 수 없음 | 정책 전 비교 기간(일 단위 약 13개월, 월 단위 15개월)과 정책 후 자료가 필요해 고를 수 있는 범위를 제한합니다 |
| 판정이 거의 '판정 보류' | 공개 데이터는 월 단위·단일 카드사이거나 측정 방식이 바뀐 경우가 있어, 결론을 낼 만큼 근거가 부족한 경우가 많습니다. '다음 할 일'의 필요 자료를 확보하면 다시 판정할 수 있습니다 |
| 화면이 열리지 않음, 포트 사용 중 | 실행.bat이 다음 빈 포트(8502 등)로 엽니다. 그래도 안 되면 `점검.bat` 보고서(`outputs\doctor\점검_*.txt`)를 확인하세요 |
| 웹 데모에서 실데이터를 새로 판정할 수 없음 | 웹 데모에는 허브 원자료를 싣지 않았습니다(재배포 조건 미확인). 설치 묶음을 쓰세요 |

**제약**
- 판정은 인과 관계를 '근거'로 제시할 뿐 단정하지 않습니다. 평행추세 같은 가정은 검정으로 완전히 증명할 수 없습니다. 판정서의 '이 분석이 말할 수 없는 것'을 함께 읽으세요.
- 카드 데이터는 비씨카드 실적이라 제주 전체 소비가 아닙니다. 비율과 변화율로만 해석합니다.
- 동시에 시행된 다른 정책의 효과는 구분하지 못할 수 있습니다. 반론 검증의 사건 달력이 아는 사건만 검증합니다.

## 9. 용어

| 용어 | 쉬운 뜻 |
|---|---|
| 대조 집단 | 정책을 받지 않아 '정책이 없었다면'을 보여 주는 비교 대상 |
| 사전 등록(잠금) | 결과를 보기 전에 분석 방법을 정해 지문을 남기는 것. 결과를 보고 방법을 바꾸는 것을 막음 |
| 위약검정 | 정책이 없던 가짜 시행일이나 가짜 대상에서도 같은 분석을 해 보는 것. 실제 효과만 튀어야 함 |
| 사전추세 | 정책 전부터 이미 있던 변화. 크면 정책 효과로 착각하기 쉬움 |
| 측정 단절 | 정책과 같은 때 데이터 집계 방식이 바뀌어 숫자만 달라지는 것 |
| 구분 가능한 최소 효과(MDE) | 이 자료로 가려낼 수 있는 가장 작은 효과 |
